# 聊天草稿切换修补（0.15.1）

## 问题与行为

0.15.0 的云端浏览器流程中，未发送草稿切换首次失败、重试通过。分析后确认：新建或打开对话会先等待本机保存，此时输入框仍可编辑；快速输入的文字因此可能写入正在离开的对话。不是通过延长测试等待掩盖问题。

0.15.1 在保存、切换和删除对话期间暂时禁用输入、发送、参数修改与重复切换，显示状态；完成后恢复。保存失败保留原对话及草稿，并恢复编辑。关闭窗口或更新应用会等待正在进行的切换。数据格式、API 协议与依赖保持不变。

## 已执行验证

- 延迟保存的确定性回归：原代码把后续文字写入旧草稿，修复后保留原草稿；同时验证重复切换不会改变目标、关闭等待切换、失败后可以继续编辑。
- 聊天组件 3 项通过；完整前端 95 文件 / 311 项与工程脚本 16 项通过，架构、类型和构建通过。保留已有焦点恢复 lint 提醒与入口包大小提示。
- 重新构建 0.15.1 后，聊天浏览器 5 个场景无重试通过，涵盖未发送草稿刷新/切换、两种 API 协议、失败重试与不同宽度和主题。

正常便携包的启动检查增加两份未发送聊天草稿往返切换，使用原生聊天库与真实 WebView；本次发布仍要求完整云端流程通过，并核对公开更新清单和文件摘要。
