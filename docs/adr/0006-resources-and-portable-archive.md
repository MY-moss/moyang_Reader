# ADR 0006：去重资源与原生便携归档

日期：2026-10-16。状态：实施并验证。

## 决定

AI 库 schema 5 使用不可变 `resources(hash, encoding, content)`。哈希覆盖编码、分隔符和原内容；当前记录、修订和待处理冲突仅保存资源引用。迁移不重新编码旧 base64，不更换原 ID、修订、共享范围或正文指纹。完整读取与 JSON 备份接口仍还原原始资源；分层和界面只读接口只投影目录，选中资源后单独加载。

资源随历史保留。永久删除后，仅清除当前记录、所有历史和冲突均未引用的资源。升级前先创建一致性快照，迁移与资源写入在同一事务中。

桌面便携备份为 ZIP：`manifest.json` 与 `library.sqlite3`。清单包含格式版本、schema、时间、字节数和 SHA-256；SQLite 自身提供分条记录与去重资源，因此不额外引入一套 JSONL 重建格式。原生层创建一致性快照、去除机器连接状态和运行队列、流式压缩、回读校验后原子发布。整个备份不经过 WebView、整库 JSON 或 base64。

恢复在所选 AI 库旁的临时目录解包和校验。逐条检查资源指纹、记录和历史，在目标事务中导入；同 ID 不覆盖。活动、检查点和合并组只有在所引用内容与目标版本相同时才恢复，否则报告跳过，避免导入的撤回操作改写本地分支。整理配置、运行锁、预留账本和客户端信任不复用。API 密钥仍在独立服务库，不包含在归档中。

旧 JSON 备份继续支持，浏览器预览仍用 JSON；桌面默认使用新版归档。文件保存位置每次由用户选择。导出临时文件位于目标目录，导入临时文件位于 AI 目录，避免大量备份临时数据落到系统盘。

## 交互和成本

草稿列表与正文、附件分开持久化，启动只读取摘要；打开某篇后才载入其内容。聊天草稿按会话异步保存，关闭等待写入；历史按 20 条分页。发送前的上下文预览显示来源、范围、层级与字节估算，排除项不会发送；资料变化后重新检索。相同内容在一次请求中只引用一份，旧对话原文保持完整。

## 依赖与证据

2026-10-16 新解析归档依赖时，crates.io 拒绝已撤回的 zip 4.6.1；统一使用当前可获取的 zip 9.0.4，并重新验证原生导出和更新验签。参见 [zip 官方文档](https://docs.rs/zip/9.0.4/zip/)。归档包含经过整理的 SQLite 数据，不是应用目录的原样复制，机器设置和运行状态会明确剔除。

验证记录见 [记忆效率升级验证](../VALIDATION-MEMORY-EFFICIENCY.md)。
