## 发现及处理

- 本机部分目录的同目录重命名返回跨磁盘错误，导致每日 AI 快照阻止打开数据库。新增仅针对该错误的复制发布处理：完整写入并同步后移除完成标记，中断副本不算有效快照。单元测试验证中断副本不会覆盖、完成后内容与完整性正确；也已在实际个人数据目录成功打开并生成快照。
- 旧工作副本使用目录链接共用依赖。早期 Git 清理连带删掉了可再生成的当前依赖，随后停止清理，按锁文件重新安装，并重新完成正常打包与便携程序实测。含目录链接的剩余副本整体移到归档；清理脚本会拒绝目录链接。
- Windows 自动审批拒绝部分旧展开目录和链接的删除，只给出策略阻止，没有详细理由。相关展开件保留在外部归档中，不进入当前工程；具体残留以本机归档索引为准。
- 已通过 Cargo 自身清理命令释放 44,600 个文件、40.8 GiB 原生构建缓存，并移除约 1.37 GiB 已解压的运行库下载包。以后只维护根目录依赖、当前模型与当前便携包。

## 仍需区分的边界

配置迁移成功不代表两个真实 Agent 的任务生命周期已验收。客户端需要重新加载连接；Codex 钩子信任、写入授权和 Claude 模型服务仍按用户决定延后。

本轮没有更改依赖版本。重新安装后的 npm 审计报告列出 29 条依赖告警，其中生产依赖为 Mammoth / argparse / sprintf-js 的 3 条中等级别告警，没有生产高危或严重告警。它们是后续依赖维护项；没有执行可能退回不兼容旧版本的强制修复。

完整 Windows 自动检查统一为根目录 `.github/workflows/quality.yml` 的 `Quality checks`，包括 24 项桌面回归；远端运行结果以本次 PR 的检查记录为准。历史检查报告中的旧子目录路径保留作为当时证据，当前使用方式见 [目录维护](../WORKSPACE.md)。
