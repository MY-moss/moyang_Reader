# 正式发布版本升级与回退

2026-10-16，在独立资料目录验证已发布的 Windows 0.13.0 → 0.14.0；没有替换更新地址、公钥或服务响应，没有使用个人笔记、记忆库或聊天配置。

## 版本与来源

- 原程序来自 [reader-v0.13.0](https://github.com/MY-moss/moyang_Reader/releases/tag/reader-v0.13.0) 的公开 ZIP，SHA-256 `4dee372dc9c6eb95e857d50f2f1af149f91a5e568a206ae15cc430be3d536ba5`，与 GitHub 资源摘要一致。
- 运行旧程序，经应用内检查与下载获得 [reader-v0.14.0](https://github.com/MY-moss/moyang_Reader/releases/tag/reader-v0.14.0)，通过正式通道签名校验后才显示“保存并重启更新”。该发布 ZIP 的 SHA-256 为 `42bd15cf4d84d0ebbaae35f5166f8fcce3c8e32bc7a53b1792f14801e617be84`。
- 新阅读器摘要 `be7aecf97c8f1df741cd11b556768cf641a7d239e92b18b2e278b44d29f5a070`，MCP 摘要 `86b91b77b4d6de4835b91cead4d2d89de74c2fad6919808d562fad68cd731f1c`；下载解包后的程序与清单一致。

## 实际结果

1. 下载后在文本编辑器输入新内容，确认磁盘仍是旧内容，随即点击“保存并重启更新”。旧程序正常退出，新程序报告版本 0.14.0，最后输入完整保存。
2. 升级前通过旧 MCP 保存的项目记忆，以及原生聊天库中的会话，在新程序中读取一致。
3. 下载目录没有模型副本。更新元数据记录原有运行程序；单独重新启动新程序、移除测试用的模型路径环境变量后，存储页面底层接口仍定位到原有模型目录及其文件。
4. 原 0.13 MCP 程序保留，升级后再次启动该原路径，能够读取同一条记忆。不会因为升级强行结束外部 Agent。
5. 独立 ZIP 首次升级没有 `previous.json`。关闭新程序、将 `updates/latest.json` 改名保留，再打开原启动入口，实际返回 0.13.0，文档和会话保持一致。已把这个首次回退步骤补入更新手册。

截图和结构化本机证据在 `artifacts/workbench/official-upgrade-before.png`、`official-upgrade-after.png` 与 `official-upgrade.json`；不上传隔离数据库。首次试跑误将已经打开的文本编辑器切回阅读模式，正式验收改为按当前模式决定是否切换，没有更改程序或放宽数据断言。

本报告证明这些已发布版本之间的实际升级。启动失败后的自动回退另由既有原生/激活脚本测试覆盖，不把本次手动回退写作崩溃恢复测试；真实外部 Agent 的钩子授权仍是独立验收项。
