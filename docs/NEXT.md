## 唯一下一步：#190 首屏加载与大文档挂载

- Issue：[在线查看 #190](https://github.com/MY-moss/moyang_Reader/issues/190)
- 优先级：Should / P3
- 风险级别：T2（加载边界、渐进渲染、构建产物和阅读回归）
- 版本分类：不单独发布；验收结果进入 `v0.11.0`

### 用户价值

减少冷启动解析成本，让大文档先显示可阅读内容，避免打开瞬间长任务和内存放大。

### 本切片范围

- 只为首屏非必需模块建立明确的动态加载边界，验证打包结果，不盲目增加 `manualChunks`。
- 公式文档首次需要时再加载 KaTeX 样式，普通文档不付出该成本。
- 把大 HTML 的拆分/挂载改为可观测的增量策略，保持目录、锚点、搜索和阅读位置正确。
- 为构建产物和大文档挂载增加最小性能证据；若基准无收益，记录数据并停止扩大范围。

### 非目标

- 不改变 Markdown 解析语义、双链语义或导出结果。
- 不为了分包引入大型运行时，不重写已经健康的 CodeMirror/Milkdown 懒加载。
- 不重复 #168 的阅读轨道优化，不顺手处理其他性能或 UI Issue。

### 验收标准

- [ ] 冷启动主 chunk 和按需 chunk 有构建前后对比记录。
- [ ] 无公式文档首屏不加载 KaTeX CSS；含公式文档首次显示公式仍正确。
- [ ] 大文档首屏先可见，后续挂载不重复处理整篇 HTML，目录跳转和阅读进度不回归。
- [ ] 至少补一条大文档挂载性能回归和一条构建产物检查。
- [ ] 相关定向测试、lint、format、一次完整构建和浏览器 E2E 通过；涉及真实桌面路径时补 Windows smoke。

### 依赖、风险与回滚

- 依赖：现有 unified 渲染链、`ProgressiveReaderContent`、Vite 构建和 #168 阅读轨道缓存。
- 风险：增量挂载可能影响全文搜索和锚点；先采用 feature-local 边界并保留同步 fallback。
- 回滚：回退本切片即可恢复现有渲染路径，避免同时改动阅读模型。
