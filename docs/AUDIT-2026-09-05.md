# 5. 外部 URL

## S-07 — browser 与 desktop 缺少统一前置 scheme validator

**严重度：Low→Medium（defense in depth / runtime consistency）**  
**状态：FIX SUBMITTED — PR #467，stacked on #463；上游合并后需 retarget main 并完成 CI**

原行为：

- Tauri 桌面端还受 capability scope 保护；
- browser/dev 路径直接 `window.open()`；
- protocol-relative URL 会继承当前页面协议。

这不是已证实的桌面 `javascript:` 可执行漏洞，因为 Tauri capability 本身仍有协议限制，但两种 runtime 的安全语义不一致。

#467 新增共享：

```ts
normalizeExternalUrl(input)
```

允许：

```text
http:
https:
mailto:
tel:
```

拒绝：

```text
javascript:
data:
file:
ftp:
unknown / malformed
http(s) 内嵌 username/password
```

并将：

```text
//example.com/path
```

确定性归一为：

```text
https://example.com/path
```

新增单测覆盖上述正/负路径。

注意：#467 为避免覆盖当前 #449→#458→#459→#463 的 `bridge.ts` 重构而采用 stacked PR；在上游未并入 main 前不能称为最终交付。

# 9. CI / 依赖安全

## C-01 — 每个 PR 都跑完整 CI，成本过高

**严重度：Medium（开发速度）**  
**状态：TRACKED — MOD-01 / MOD-02**

当前每个 main-target PR 都会执行 frontend coverage/build、browser E2E、desktop smoke、release checks、Rust fmt/clippy/test 等完整矩阵。

正确提速方式是 scope-aware，而不是删真正的安全测试：

```text
PR -> changed-path scope -> targeted lane
main / checkpoint / release -> full lane
unknown infra -> full
```

## C-02 — 依赖审计基础已经存在

**结论：已有基础机制。**

CI 包含：

```text
npm audit --omit=dev --audit-level=high
```

仓库另有 Rust audit workflow 与 Dependabot。依赖风险必须继续以最新 CI/Dependabot 为准，不能因为本审计通过就宣称“永久安全”。
