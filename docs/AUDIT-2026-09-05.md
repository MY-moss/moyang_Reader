# 4. Tauri 权限

## S-05 — `process:default` 比实际调用更宽

**严重度：Low→Medium（最小权限）**  
**状态：FIX SUBMITTED — PR #466**

Tauri v2 官方说明 `process:default` 包含：

```text
allow-exit
allow-restart
```

当前 `src/app/updater.ts` 的 plugin-process 调用只使用 `relaunch()`。

#466 改为：

```text
process:allow-restart
```

移除未使用的 `allow-exit`。

## S-06 — `opener:default` 包含未使用 reveal 权限

**严重度：Low→Medium（最小权限）**  
**状态：FIX SUBMITTED — PR #466**

Tauri v2 `opener:default` 包含：

```text
allow-open-url
allow-reveal-item-in-dir
allow-default-urls
```

前端 `bridge.openExternalUrl()` 只用 `openUrl()`；工作区资源管理器定位走项目自己的授权 Rust 命令。

#466 改为：

```text
opener:allow-open-url
opener:allow-default-urls
```

不再授予 plugin opener 的 reveal command。

# 5. 外部 URL

## S-07 — 前端缺少统一显式 scheme validator

**严重度：Low→Medium（defense in depth / dev-browser consistency）**  
**状态：TRACKED — B03；不要与 #449/#458 当前 bridge stack 冲突**

当前 `openExternalUrl()`：

- Tauri 生产环境还有 capability scope 限制，默认只允许 http/https/mailto/tel；
- 浏览器预览路径直接 `window.open()`；
- 协议白名单主要依赖 Tauri capability，而不是纯前端共享 validator。

因此当前桌面生产环境已有关键防线，并不是已确认 `javascript:` 可执行漏洞；但为避免 browser/dev 与 desktop 语义分叉，应在 #449/#458 bridge contract 稳定后补：

```ts
normalizeExternalUrl(input)
allowed: http:, https:, mailto:, tel:
reject: javascript:, data:, file:, unknown scheme, malformed URL
protocol-relative -> deterministic https:
```

并为两种 runtime 共用同一 validator。

这个切片已经属于当前 `AI-TASKS` B03 的验收范围，不应另开一个与 bridge stack 冲突的平行改动。

# 9. CI / 依赖安全

## C-01 — PR 全量 CI 成本高

**严重度：Medium（开发速度）**  
**状态：TRACKED — MOD-01 / scope-aware CI**

当前每个 PR 都执行 frontend coverage/build、browser E2E、desktop smoke、release checks、Rust fmt/clippy/test 等完整矩阵。

安全性强，但会拖慢多个 AI 并行。

正确优化不是删测试，而是 scope-aware：相关 PR 跑相关测试，main/checkpoint/release 继续 full lane。

## C-02 — 依赖审计已经存在

**结论：基础机制存在。**

CI 已包含：

```text
npm audit --omit=dev --audit-level=high
```

仓库也有独立 Rust audit workflow / Dependabot。后续仍以最新 CI/Dependabot 为真实漏洞状态，不能仅凭本审计文档宣称“依赖永久安全”。
