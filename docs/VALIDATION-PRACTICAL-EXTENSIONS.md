# 实用扩展交付验证（0.14.0）

## 本轮发现与补齐

现有市场已支持阅读、主题、技能、MCP 和聊天助手，但阅读工具只有两项，结果缺少复用出口，安装后主要依赖命令面板。此次增加四项离线工具、两个助手和一项来源核对技能；直接运行、来源定位、报告复制和文本附件导出形成完整路径。

现有工作台、索引调度、异步草稿和撤销预算继续沿用。没有新增模型服务或后台常驻插件；Markdown 解析仅在运行需要它的插件时执行。

## 验证

- 前端 303 项测试通过；工程脚本 16 项通过。
- 新插件用真实可分发代码验证任务、引用式链接、转义表格、公式文本、结构建议及空文档；旧 report/replacement 协议仍有效。
- 浏览器全量 98 个场景中，初次 97 项通过；新增助手测试修正“尚未配置 API 时不展示开场问题”的预期后，四项新增流程全部通过。包含直接运行、原文选中、实际 CSV 下载、启停卸载、助手选择和技能资源预览。
- 真实 Windows 桌面 29 项通过，包括后台 Worker 解析 Markdown、定位原文、经原生保存接口导出 CSV，以及已有读写、恢复、聊天和签名更新流程。
- 浅深色、720/1440 宽度的新增结果窗口无横向溢出或自动化无障碍违规，已查看截图。它不代替所有系统缩放和辅助设备的人工验证。
- 架构、格式、静态检查与生产构建通过；保留原有焦点恢复 lint 提醒和主包大小提示，不把这些提醒算作测试失败。
- 正常 0.14.0 便携包已实际启动，Windows 150% 缩放、正式构建中的新插件、MCP 写入/召回/更正/恢复、本地中文嵌入、聊天配置、存储页和正常关闭通过。开发模式的后台解析与实体解码也单独验证通过。
- GitHub 变更位于 [PR #582](https://github.com/MY-moss/moyang_Reader/pull/582)，合并状态和完整云端检查以该页面为准；发布文件及签名校验见 [0.14.0 发布页](https://github.com/MY-moss/moyang_Reader/releases/tag/reader-v0.14.0)。
- 浏览器首次实测发现解析器选择了依赖 DOM 的实体解码入口，Worker 报错。构建改用同包提供的无 DOM 实现，并以实际 Worker 复测。
- 发现运行时序列化函数会让开发包、压缩包和线上目录的同版本代码不同；改为统一生成固定包，并增加生成物一致性检查。

## 已知边界与后续价值

链接清单只整理当前 Markdown 的链接、图片和引用式链接，不包含双链，也不验证远端可达性。文档体检只给结构建议，不做事实核查。CSV 导出可读单元格文字，公式样式按文本保存；最多一次 32 张表。PDF 选字/页内高亮、OCR、跨文件任务看板、Canvas/Dataview 和复习排程仍未实现，没有以同名空入口代替。

真实外部 API 的答案质量与客户端自动沉淀仍依赖用户服务和客户端授权；此次助手使用现有协议能力，验证安装和切换，不以模拟回答声称模型效果通过。验证只覆盖正常功能与数据保持，不做人工规模压测。
