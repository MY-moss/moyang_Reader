# v0.9.0 功能需求与验收

## 产品边界

- Windows x64 单平台、本地优先、离线可用；不做用户文档云同步。
- Windows 是唯一的产品、发布、安装包、文件关联、自动更新和真实桌面 E2E 平台。
- 浏览器版只用于本地开发预览和 Playwright UI 测试；macOS、Linux、Windows ARM、移动端和跨平台自动更新不属于当前支持范围。
- 默认 CI 只运行 Windows 质量门禁；保留独立 RustSec 依赖审计不等于支持 Linux 产品。
- Markdown 是持久化真源；所见即所得编辑器不得静默删除未知语法。
- Markdown 默认进入所见即所得编辑；TXT/LOG 使用纯文本编辑；DOCX、PDF 和图片在 v0.9 只读。
- 现有文件打开、文件夹工作区、标签页、双链、搜索、导出和更新能力必须保持可用。
- 首次启动必须提供可关闭、可重新打开的快速上手教程，覆盖打开文档、添加阅读库、编辑、搜索、导出和更新；教程不得阻塞后续正常使用。
- 设置修改后必须提供可见的保存状态；本机存储写入需要校验，Windows 桌面端必须有应用配置文件兜底，双重存储均失败时必须明确提示且不得声称保存成功。

## v0.10.13 草稿恢复差异预览（#323）

- 恢复草稿前必须先展示当前版本与草稿的可理解差异摘要，至少包括草稿保存时间、新增行、移除行和字符变化。
- 必须提供有限的逐行差异预览；预览超过上限时明确提示已截断，不得把部分预览伪装成完整比较。
- 当前文档的比较基线是当前磁盘版本；从恢复中心查看其他文档时，比较基线是草稿保存时记录的原文。若当前磁盘内容已偏离该原文，必须提示用户。
- 当前编辑区存在未保存内容时，恢复前必须提示恢复会替换编辑区内容；恢复动作只能把草稿放入编辑区，不得自动写回磁盘，用户仍须显式点击保存。
- 差异对话框必须支持取消和 Escape 关闭；只有点击明确的恢复动作才允许进入恢复流程。对非当前文档，确认动作先打开文档并让用户再次查看当前文档提示，不得在恢复中心直接覆盖文件。
- 草稿内容与其 `baseSource` 完全相同时，不应继续作为可恢复草稿展示；行尾差异不得被误报为正文变更。
- 草稿差异必须支持多个分散变更区域；小范围统计应精确显示新增/移除行，超出快速比较边界时必须明确标注摘要性质并建议在编辑区复核，不得把估算伪装成完整比较。
- 恢复前必须明确告诉用户是否存在可恢复内容：无差异时显示“无需恢复”并禁用恢复动作；有差异时说明恢复只替换编辑区，磁盘版本在草稿后变化时优先提示核对。

### v0.10.13 草稿恢复验收场景

- 当前文档存在草稿时，提示区显示差异摘要；点击“查看差异”能看到统计、变更行和未保存风险。
- 恢复中心中的非当前文档可以打开差异预览；点击取消或 Escape 后草稿和编辑区均不改变。
- 点击“恢复到编辑区”后，正文变为草稿内容但文件尚未改变；点击保存后才写回文件。
- 草稿保存后磁盘发生变化时，差异窗口显示风险提示；等价于基线的陈旧草稿不会出现在恢复列表。

## v0.9.0 必须完成

1. 三栏职责明确：左侧工作区导航，中间阅读/编辑，右侧上下文。
2. 右侧可显示目录、关联内容和属性摘要；关系图作为“关联”视图中的明确动作打开，不单独占用一个只有按钮的页签；窄窗口改为可唤起抽屉。
3. Markdown 编辑器按需加载，不影响空白启动和只读文档启动。
4. Markdown 支持源码/所见即所得切换；解析或序列化不安全时回退源码并说明原因。
5. 保留现有快捷键，并加入编辑切换、命令面板、保存、插入链接等命令。
6. 布局、上下文面板和编辑模式状态在本机持久化。
7. 同步更新测试、架构、路线和 AI 交接文档。
8. 多个本地文件夹可以同时挂载并独立保留文件树、筛选、标签页和当前文档；切换已挂载阅读库优先使用内存会话，不得覆盖或清空其他阅读库。
9. 已打开 Markdown 时，顶部必须提供直接的“编辑 / 阅读”主动作；进入编辑后默认使用所见即所得模式，源码模式保留在更多工具中作为保真回退路径。
10. Windows Debug 和 Release 桌面进程都使用 GUI 子系统，不得额外弹出会随应用退出的 CMD 控制台窗口；开发用 Vite 服务也不得创建独立控制台窗口。

## 明确后置

- 显式块 ID、块引用、完整属性编辑和关系图筛选进入 v0.10。
- 大规模搜索、Worker 导出、跨平台发布和代码签名不混入 v0.9.0；跨平台发布在 v1.0 前不纳入主线。
- 不引入外部任意脚本插件、账号、云同步或移动端。

## v0.10.4 工作区与编辑上下文菜单（#232）

- 左侧工作区必须提供可发现的“新建”入口，支持在根目录新建 Markdown 笔记和文件夹；笔记创建成功后打开，文件夹创建成功后立即在树中显示。
- 文件夹右键菜单和键盘 Context Menu / `Shift+F10` 必须提供在当前目录新建笔记/文件夹的快捷动作；名称校验不得允许路径穿越、Windows 保留设备名或非法文件名字符。
- 空文件夹必须是真实目录，不得通过 `.keep`、占位 Markdown 或其他污染用户工作区的方式实现；工作区重载和外部 watcher 刷新后仍能显示。
- 正文编辑模式右键菜单必须保留当前选区，并提供常用格式、段落和插入动作；源文本动作按一次操作进入应用级撤销历史，WYSIWYG 动作复用现有 Milkdown schema。
- 阅读模式不拦截系统右键菜单；菜单必须支持 Escape、外点关闭、首项聚焦和键盘上下导航；创建失败要显示可理解的原因，不吞掉磁盘错误。
- 本切片不实现重命名、删除、拖拽移动、插件市场、Canvas、Dataview 或完整 Obsidian 插件兼容；这些能力另行进入 Ready backlog。

- 标签页支持鼠标中键关闭和原生 HTML5 拖拽排序；拖拽过程中显示源标签和目标标签状态，不依赖新增运行时包。
- 阅读区支持连续缩放：Ctrl+滚轮每次调整 5%，Ctrl+=/Ctrl+- 每次调整 10%，Ctrl+0 恢复 100%；设置提供 75%–150% 的可访问滑块。
- 缩放只影响阅读视图的屏幕呈现，不改写 Markdown 真源、导出内容或编辑器内部字号；旧版 `readingScale` 偏好应自动迁移。

### v0.10.4 验收场景

- 在根目录和嵌套空文件夹分别新建笔记/文件夹，关闭并重新打开工作区后目录仍存在，笔记内容为有效 Markdown。
- 右键文件夹、右键文件所在目录、使用 `Shift+F10` 打开菜单，动作目标目录一致；点击菜单外或 Escape 后菜单关闭且焦点行为正常。
- WYSIWYG 和源文本分别对选中文本应用格式、对空选区插入双链/图片/表格，保存后 Markdown 可读且没有静默删除已有内容。
- TXT 能使用源文本菜单；DOCX、PDF、图片和阅读模式不显示编辑菜单。

## v0.10.5 文件管理与文本编辑上下文（#232 后续）

- 文件和文件夹右键菜单必须提供打开/定位、重命名、删除和复制完整路径；删除文件夹前必须明确确认并递归删除其内容，不能删除工作区根目录。
- 重命名文件夹后，打开标签页、最近打开、当前文档和工作区索引必须同步改用新路径；重命名当前未保存文档或删除包含未保存文档的条目时，必须先提供保存确认，保存失败则取消操作。
- 文件管理必须限制在已授权工作区内；拒绝路径穿越、工作区外路径和最终符号链接，资源管理器定位使用无控制台窗口的 Windows 原生调用。
- 正文编辑模式右键菜单必须提供撤销、重做、剪切、复制、粘贴、全选，并继续保留格式、段落和插入动作；这些动作与现有应用级编辑历史保持一致。

### v0.10.5 验收场景

- 右键文件可打开、重命名、删除、定位到资源管理器和复制完整路径；右键文件夹可在当前目录新建、重命名、递归删除、定位和复制路径；空工作区根目录仍能打开根菜单。
- 重命名打开文件或文件夹后，标签页、最近打开和当前文档路径不失效；删除当前文件后自动打开相邻标签页或回到空状态；未保存修改未确认保存时，文件系统不发生变化。
- 文件管理拒绝空路径、路径穿越、工作区外路径、目标重名和最终符号链接；Windows 资源管理器定位不创建额外控制台窗口。
- 源码和 WYSIWYG 右键菜单中的撤销、重做、剪切、复制、粘贴、全选分别作用于当前编辑器，失败时显示状态提示且不吞错。

## v0.10.6 文件管理与编辑扩展（#232 后续）

- 文件和文件夹右键菜单提供“复制文件/复制文件夹”；副本在原条目同级创建，文件默认保留原扩展名，文件夹递归复制内容。
- 文件树右键提供“复制相对路径”和文件夹展开/折叠；路径复制不改变当前文档、筛选或标签页状态。
- 副本命令只能作用于已授权工作区内的相对路径；拒绝路径穿越、目标重名、最终符号链接以及副本中的嵌套符号链接，不允许把工作区根目录作为复制源。
- 正文右键菜单增加清除常见 Markdown 格式、任务列表和插入今天日期；清除格式必须有选区，任务列表对当前行/选区幂等，日期使用 `YYYY-MM-DD`。
- 本切片不实现文件移动、回收站撤回、批量复制、版本历史或 DOCX/PDF 原格式编辑；这些能力另行评估，不得从“删除”推断出可恢复保证。

### v0.10.6 验收场景

- 右键 Markdown、TXT、图片或 PDF 对应的文件树条目，复制文件/文件夹后副本出现在同级，内容可读取，重名和越界名称得到明确错误。
- 右键嵌套文件夹可折叠/展开；复制相对路径得到工作区内路径，不会意外复制绝对路径或切换当前文档。
- 源文本和 WYSIWYG 中分别选中文本执行清除格式、对普通段落执行任务列表、插入日期；撤销历史仍由应用统一管理。

## v0.10.8 右键管理增强（#232 后续）

- 文件和文件夹右键菜单必须提供“查看属性”，至少展示名称、类型、工作区相对路径、完整路径，以及文件大小或文件夹包含的文件数；查看属性不得改变当前文档、筛选或标签页状态。
- 标签页右键菜单必须提供关闭当前、关闭其他、关闭右侧和关闭全部；批量关闭仍复用当前文档未保存确认，取消或保存失败时不得关闭任何目标标签。
- Markdown 所见即所得和源文本编辑器右键菜单必须提供“查找选中文本”，打开当前文档搜索并填入选区内容；没有选区时动作禁用或给出明确提示。
- 本切片不实现文件移动、回收站恢复、批量文件操作、属性写回或 DOCX/PDF 原格式编辑；这些能力继续单独评估。

### v0.10.8 验收场景

- 右键文件和文件夹选择“查看属性”，弹层显示正确的类型、相对路径、完整路径和大小/文件数；Escape、关闭按钮和弹层外点击均能关闭，焦点回到原触发条目。
- 右键任意标签页，关闭其他或关闭右侧只影响对应集合；关闭当前/全部遇到未保存文档时只询问一次，取消后标签页保持不变。
- 在 Markdown 的 WYSIWYG 和源文本模式选中文字，右键“查找选中文本”后搜索框可见且内容等于选区；普通格式、保存、撤销和已有文件树 CRUD 不回归。

## v0.10.9 右键快速管理补全

- 文件树右键必须提供当前范围刷新、复制文件/文件夹名称；文件夹必须可复制相对路径，当前活动文件必须可从文件树关闭标签。
- 阅读模式正文必须支持右键复制/查找选中文本；右键链接必须提供复制地址和打开链接；可编辑文档必须可以直接进入对应编辑模式，并可复制本地文档路径。
- 阅读模式右键打开内部双链、标题锚点、本地文档和外部链接时，必须与正文左键使用同一解析和安全协议边界；右键操作不得切换文档或丢失选区。

### v0.10.9 验收场景

- 右键根目录、文件夹和文件，刷新动作只刷新对应工作区范围；复制名称/相对路径得到预期值，当前活动文件可关闭标签，其他文件不出现误导性的关闭动作。
- 阅读 Markdown 为阅读模式时，选中文本后右键可复制和查找；右键外部链接可复制地址或打开，右键内部双链/标题锚点仍能正确导航；右键空白处可进入编辑或复制本地路径。
- 浏览器预览、TXT、Markdown 和不可编辑文档的菜单只显示适用动作；复制失败、路径无效或链接不受支持时有明确状态提示，不吞掉错误。

## v0.10.10 工作区转移与纯文本粘贴

- 文件和文件夹右键必须支持“剪切到其他文件夹”和“复制到其他文件夹”，目标可以是工作区根目录或任意已存在的子文件夹；操作只能发生在已授权工作区内。
- 粘贴必须拒绝目标重名、把文件夹粘贴到自身或自身子目录、路径穿越和最终符号链接，不覆盖已有条目；复制可重复粘贴，移动成功后清除待粘贴状态。
- 移动打开中的文件或文件夹后，当前文档、打开标签页、最近记录和缓存路径必须同步更新；未保存文档受影响时先请求保存，保存失败或取消时文件系统不得改变。
- Markdown、TXT 源文本和 Markdown 所见即所得编辑器必须提供“粘贴为纯文本”，不得把剪贴板 HTML 标记带入 Markdown；普通“粘贴”保持现有纯文本安全边界。
- 本切片不实现跨工作区移动、回收站恢复、批量转移、覆盖粘贴或用户文档云同步。

### v0.10.10 验收场景

- 在根目录和嵌套文件夹之间分别复制/移动文件与文件夹；复制结果可再次粘贴，移动结果不残留源条目；同名和自身子目录目标得到明确提示。
- 移动当前打开文件和包含打开文件的文件夹后，标签页、当前文档、最近记录和索引仍指向新路径；存在未保存内容时取消确认不会改变磁盘。
- 在 Markdown 源文本、Markdown 所见即所得和 TXT 中从右键执行“粘贴为纯文本”，HTML/富文本剪贴板不会产生 HTML 标签；撤销历史和保存不回归。

## v0.10.13 编辑格式与插入体验（#321）

- WYSIWYG 与 TXT/Markdown 源文本编辑器必须显示统一的轻量编辑工具栏，覆盖撤销、重做、粗体、斜体、删除线、行内代码、清除格式和正文/标题/列表/引用/代码块/任务列表等段落动作。
- “插入”必须使用应用内紧凑面板，提供链接、Obsidian 双链、图片和可配置表格四类入口；不能调用浏览器 `window.prompt`，Escape、取消、外点和提交后的焦点行为必须可预测。
- 链接支持编辑显示文字、地址和可选提示；双链支持目标和可选别名；图片必须分别收集路径/URL 与替代文字，不能把路径错误写入 alt；表格至少 2×2，最多 8×8，首行为表头。
- WYSIWYG 插入使用现有 Milkdown schema/命令，源码插入使用统一 Markdown 构造函数；Markdown 仍是真源，插入失败或当前正文已变化时不得覆盖最新内容。
- 插入地址拒绝可执行协议；未知 Markdown 结构、frontmatter 和既有内容不因工具栏操作静默丢失。

### v0.10.13 验收场景

- 在 WYSIWYG 选中文字打开“插入”，输入地址后生成可序列化的 Markdown 链接；在源码模式用同一面板插入图片和自定义行列表格。
- 工具栏的格式/段落动作与右键菜单作用于当前选区；编辑器获得焦点后 `Ctrl+K` 打开链接面板，不能出现浏览器原生弹窗。
- 关闭面板、按 Escape、点击外部或提交后，正文内容、光标和未保存状态保持一致；面板打开期间正文被外部更新时拒绝覆盖并给出提示。
- 链接、图片和表格经过 WYSIWYG↔源码切换后内容可读；TXT 仍为纯文本编辑，DOCX/PDF/图片只读，不出现编辑工具栏。

## 验收场景

- 空白启动不加载所见即所得编辑器。
- 双击 Markdown 可编辑，切换源码后内容不丢失。
- 同时挂载两个本地文件夹，切换后各自的文件树、筛选、标签页和当前文档不串库；达到挂载上限时必须明确提示，不能静默挤掉旧阅读库。
- 打开 Markdown 后可以不经过“更多”菜单直接进入和退出所见即所得编辑；输入变化即时反映到当前草稿，保存仍由 `Ctrl+S` 或保存动作明确写回文件。
- 打开 TXT 仍为 CodeMirror，打开 PDF/DOCX/图片不会显示编辑工具。
- 左栏筛选、中央标签页和右栏目录/关联内容互不抢占状态。
- 收起左右面板、进入专注模式、切换主题和窄窗口布局均可恢复。
- 未保存修改、外部文件修改和保存失败均有明确提示。

## 模态弹层键盘契约（#186）

- 所有 `aria-modal="true"` 弹层打开后必须把焦点放到明确的初始控件；没有合适控件时才聚焦弹层容器。
- `Escape` 关闭当前弹层，不能继续触发背景页面快捷键；关闭后把焦点归还到打开弹层前仍存在的触发控件。
- `Tab` 和 `Shift+Tab` 必须在当前弹层内循环，不能把焦点移到被遮挡的背景页面；弹层内容变化后焦点列表按当前 DOM 重新计算。
- 该契约适用于命令面板、快速打开、草稿恢复、关系图、打印预览、未保存退出确认和外部覆盖确认；上下键、Enter、鼠标关闭等业务行为继续由各弹层自身处理。

## 工作区文件列表交互约束

- 文件树始终展示当前筛选后的完整文件集合，不使用任意数量截断，也不再提供“显示全部 / 收起列表”这种二次展开按钮；文件树、搜索和 `Ctrl+P` 各自承担目录浏览、内容检索和快速定位职责。
- “打开列表”批量塞入标签页的入口已移除；需要批量处理时使用系统多选打开或批量导出，避免一次操作制造大量标签页。
- “添加整个文件夹”在同一界面只保留一个可见入口：侧栏展开时由当前上下文承接，侧栏收起后由顶部按钮承接；快捷键和命令面板不因视觉入口收敛而失效。已有阅读库且未选中文档时，空白主区不重复引导添加文件夹。
- 批量导出只在已有阅读库且当前筛选范围包含 Markdown、纯文本或 Word 时显示；没有可导出范围时不显示空菜单。
- 超大工作区的虚拟化、增量渲染和 Rust 端规模保护仍属于 #169 / v0.10.1，不得用前端静默截断伪装成性能优化。

## 更新提示交互约束（#192）

- 更新下载进行中必须显示明确进度；用户可以隐藏提示，下载继续在后台进行，不得把“隐藏”误实现为关闭或丢弃更新资源。
- 顶部更新入口在下载期间显示“下载中…”，可以重新打开当前下载进度；不能因为提示被隐藏而重新发起一次检查或下载。
- “启动时检查更新”只在应用启动时读取一次；用户在当前运行期间打开或关闭该设置，不应立即触发检查，下一次启动才生效。
- 当前 Tauri updater API 没有可靠的 AbortSignal 取消接口，因此 v0.9 不承诺伪造“取消下载”按钮；如果未来升级依赖并获得可验证的取消能力，再单独设计取消与清理语义。

## v0.9.1 编辑稳定化补充

- 工作区监听发现当前文档被外部修改且没有本地未保存编辑时，自动重新读取磁盘内容；WYSIWYG 编辑器必须同步到新 Markdown，且不能因为这次同步重新标记为未保存。
- 当前文档同时存在本地未保存编辑和外部修改时，只显示冲突提示，不自动覆盖编辑内容；用户点击“重新载入”后，先保存草稿恢复副本，再二次确认是否丢弃当前编辑。
- 外部修改提示的“稍后处理”只能隐藏提示，不能清除保护状态；标题、标签、正文信息或底部状态必须保留可发现的外部修改标记。普通保存必须拦截并提供重新载入、覆盖保存、另存为三种明确路径；覆盖保存前必须复核磁盘内容并经过应用内确认。
- 应用自身保存产生的 watcher 事件必须被短时抑制，避免保存后立即触发外部修改提示或重复读取。
- 源码模式和 WYSIWYG 编辑器输入 `[[` 时提供工作区 Markdown 文档双链补全：键盘上下选择、Enter/Tab 确认、Escape 关闭；补全候选不包含当前文档，同名文档用相对路径区分。
- 为 Milkdown 支持的语法维护 round-trip 样例集（标题、行内样式、双链、列表、任务列表、引用、代码块、表格、图片、分隔线），e2e 断言经 WYSIWYG 序列化后内容无损；发现新语法不保真时要么补充安全回退，要么从样例集移除并记录原因。
- WYSIWYG 和渲染模式的草稿渲染必须使用可取消的短防抖；快速输入期间合并中间状态，旧的异步渲染结果不得覆盖最新草稿。当前基线为 180ms，后续如调整必须有基准或回归测试支撑。
- 阅读位置必须按文档路径独立保存；切换或关闭文档时只能写入该文档最后一次已知的滚动位置，不能从已经渲染新文档的共享滚动容器读取旧文档位置。进入阅读模式并完成正文布局后必须重新应用已保存位置，必要时在有限动画帧内重试，确保从 WYSIWYG/源码切换到阅读时也能恢复。无效或负值按 0 处理。
- 切换文档、关闭当前标签、打开新文件、创建并切换到新笔记或切换阅读库前，必须同步冲刷当前可编辑本地文件的最新草稿，不能依赖 1.5 秒自动保存计时器；草稿保存失败时阻止切换并保留当前编辑。桌面本地文件成功冲刷后，确认文案必须说明草稿可在“草稿”中心恢复；浏览器临时预览没有持久化草稿能力，继续显示未保存修改警告。

### v0.9.1 编辑历史与恢复补充

- Markdown 和纯文本的源码/所见即所得编辑共用同一个应用级编辑历史；Markdown 文件仍是唯一持久化真源，历史只保存在当前会话内。
- `Ctrl+Z` 撤销、`Ctrl+Y` 或 `Ctrl+Shift+Z` 重做；编辑工具栏、命令面板和键盘操作必须使用同一套状态，不能让两个编辑器各自维护一份互相打架的历史。
- 打开、切换或重新载入文档时重置历史；保存不会清空历史，保存后继续撤销必须重新标记为未保存并要求用户再次保存。
- 历史最多保留 100 个编辑状态；新编辑会清空重做分支，重复状态不得制造空历史项。历史回退只允许发生在源码或所见即所得编辑模式，阅读模式不能通过命令面板修改草稿。
- 外部文件刷新、WYSIWYG 的受控源码替换和编辑器卸载冲刷不得重复记录为新的本地编辑；无法安全 round-trip 的 Markdown 继续回退源码模式，不得因撤销/重做静默删除未知语法。

## v0.9.4 标签页文档缓存（#183）

- 本地文档缓存只存在当前应用进程内，不写入用户文档目录，不参与云同步，Markdown 文件仍是唯一真源。
- 缓存键由规范化 Windows 路径和 `size`、`modifiedMs` 文件标记组成；标签页切换命中时不得再次读取磁盘或重新运行相同的 Markdown/Word 准备流程。
- 缓存最多保留 32 条，估算总内存上限为 64 MiB；单个条目超过预算时直接跳过缓存，不能为了命中率无限保留大文件。
- 工作区 watcher 收到文件或目录变更、文档成功保存、标签页关闭和应用退出时必须清理相应缓存；文件大小或修改时间变化时不得使用旧内容。
- 缓存不可用、元数据读取失败或条目类型不匹配时，必须回退现有的磁盘读取和错误提示路径，不影响 Markdown、TXT、DOCX、PDF 和图片的既有打开行为。
- 验收：缓存纯逻辑测试覆盖命中、失效、LRU、目录失效和内存上限；桥接测试覆盖轻量文件标记；前端完整测试、构建、浏览器 E2E、Rust 测试和真实 Windows 桌面回归均通过后，才可纳入 v0.9.4 安装包。
