结论：现用记忆库和 MCP 的保存、读取、检索、历史及恢复链路可用。实测发现连接状态误报，修补版 0.15.2 修复同一 Windows 路径不同写法的识别。聊天与所有客户端自动沉淀不能据此全部标为验收完成。

## 本轮发现与修复

本机配置使用正斜杠数据目录，桌面解析的相同目录使用反斜杠。原实现直接比较配置文本，实际读写成功时仍报告“未配置”，并隐藏连接回执。

0.15.2 对已由本应用登记的程序和数据目录比较实际路径；目标相同时继续使用原有配置写法和钩子定义。不会仅因路径写法不同而改写客户端文件、更新安装时间或重新要求信任。真正不同的程序、目录和未知配置仍保持区分。

Windows 回归在原实现稳定失败；修复后验证 Codex、Claude 的状态与幂等安装，配置文件、钩子、安装时间和原回执均保持不变。已有配置合并、占用失败恢复与回执归属测试一起通过。

## 自动沉淀与聊天边界

- 当前 Codex MCP 已连接 0.15.1，真实工具写入可用；本轮任务检查点由真实用户输入钩子创建，但其执行来源仍是旧版本。先前真实检查点的结论已保存并读回；新版结束钩子没有完成回执时，不标为新版自动沉淀已验证。
- 隔离测试验证 Codex、Claude 的提示去重、中断恢复、最多一次补充、补充沿用原检查点、重复完成不重复写入。它证明生命周期实现行为，不等同于真实客户端信任和模型调用。
- Claude 配置已有，但其本机转发服务连接失败，没有真实 MCP、钩子或完成回执；按用户此前安排暂缓真实验收。
- 个人应用没有聊天 API 配置，不能验证实际生成回答；嵌入模型只用于检索，不是聊天模型。
- 没有长期新结论时，任务可以完成检查点而不新增记忆。临时测试样本不会成为长期用户事实。
