# 迁移、归档与恢复

## 记忆效率升级：AI schema 5 与便携备份

本次按顺序升级派生概览、整理队列和去重资源结构。旧库升级前先生成 `snapshots/upgrade-*.sqlite3`，迁移事务保留 ID、修订、资源原字节和旧 Agent 私有范围。资源正文不再随每一版本重复存储；历史读取和恢复仍返回同样的附件。

桌面“AI 空间 → 接入与备份 → 导出完整备份”保存带校验清单的 ZIP，每次可选择磁盘和文件名。导入同时支持新版 ZIP 与旧 JSON，同 ID 跳过；损坏文件不会部分写入目标库。合并组可随新版备份恢复并撤回，遇到同 ID 的不同本地内容时跳过关联活动并说明数量。备份不含 API 密钥，不恢复运行锁、客户端信任或自动启用整理。需要完整搬家时，用“设置 → 存储位置”迁移独立服务 / 聊天目录，保留原 API 配置。

新库不能直接交给旧程序写入。回滚程序时，应把升级前快照恢复到独立目录，再接入旧版本；不得将旧快照覆盖仍在使用的新库。界面草稿数据库升级会保留旧草稿并补充摘要，旧聊天草稿读到后才转入异步存储；迁移成功前保留旧副本。

模型、AI 库、自动快照、服务 / 聊天、扩展、界面缓存和应用下载版本均可分别迁移，详情见 [后台整理与模型说明](BACKGROUND-ORGANIZATION.md)。父目录迁移保留已分离的目录链接；旧 MCP 路径与快捷方式继续可用。

## 0.12 扩展数据

0.12 沿用 0.11 的笔记和 AI 数据格式、ID、范围及历史，不扩大 Agent 的可见内容。插件安装另存于应用配置目录 `extensions/extensions.sqlite`。需要迁移完整扩展环境时，先关闭程序，复制整个 `extensions` 目录；AI 技能内容仍走 AI 备份，阅读资料仍需单独保留。客户端连接在新机器重新预览安装，不能直接照搬旧机器的程序路径。

AI 日/周快照使用 `.rotation.lock` 协调桌面与多个 MCP 进程。锁由操作系统随进程释放；存在这个文件本身不代表被锁住，无需手动删除。2026-10-16 目录整合后，本机仅保留当前便携包；历史程序在外部归档中。实际路径见 [目录维护](../WORKSPACE.md)，旧验证报告中的路径是当时的历史记录。

## 工程迁移

当前工程从原 `moyang-reader-next/` 提升到仓库根目录。Git 历史与原分支保留；旧工程、所有工作副本独有源码和未提交改动已先归档并校验，再从工作位置移除。详细归档索引在项目旁的 `本地阅读工具-归档/2026-10-16/`，不上传个人归档。

可以把本目录整体复制到任意新路径，执行 `npm ci`。所有前端相对导入指向本目录 `src/`，桌面配置的 `frontendDist` 指向本目录 `dist/`。不创建指向父项目源码的软链接。

## 用户数据并存

开发版应用标识 `com.moyang.reader.next` 与原版 `com.moyang.reader` 分开，因此原生设置和 WebView 数据目录可以隔离。开发版不注册文件关联，不配置旧版 updater 地址。不要同时以两个开发进程使用 1420 端口。

两个版本仍可以打开同一真实文档，这意味着它们会操作同一个文件。先保存或另存当前编辑，避免两个窗口同时修改同一文件。外部修改检测保留，但不能代替版本备份。

## 推荐迁移步骤

1. 在旧版保存所有编辑，确认需要保留的草稿已导出或保存。
2. 从旧版设置导出 JSON，保留原文件。
3. 启动新版，先打开少量测试文档，确认渲染和编辑符合预期。
4. 在新版设置导入 JSON；阅读库路径重新选择或重新授权。
5. 测试一次保存、外部修改冲突、HTML/DOCX/PDF 导出。
6. 正式切换前备份重要资料。删除旧工程前校验其归档，个人阅读库与应用数据单独保留。

## 回滚

新版设置使用应用配置目录的 `settings.sqlite`，首次读取兼容旧 `settings.json` 并保留旧文件。新版阅读数据包括应用数据目录中的 `reader.sqlite`（收藏、摘录、保存视图、历史与可重建索引），以及每个阅读库内的 `.moyang/recycle`。完整备份时先退出应用，再复制阅读库和应用数据目录；运行中不要只复制 SQLite 主文件而漏掉 WAL。回收站默认保留 30 天，笔记历史最多 50 个版本，连续自动保存按 60 秒合并。

重命名会先保存可恢复的操作记录。正常完成或完整撤销后记录删除；如果同时发生外部修改，提示会指向 `.moyang/operations/rename-*.json`。遇到这种情况先复制整个阅读库和该记录，再核对 `original`、新名称、每个链接文件的 `before` 与 `after`。仅在当前内容等于记录中的 `after` 时采用对应 `before`；若不同，保留双方内容，在应用中比较合并。不要用整批覆盖处理已经被其他程序继续修改的文件。确认文件路径和链接一致后再移走操作记录。

需要旧工程时，将外部归档的 `original-root.zip` 解压到另一个空目录，执行 `npm ci`；历史提交可从 `repository-history.bundle` 克隆。不要解压覆盖当前工程，不要用旧数据覆盖仍在使用的应用数据。用户文档格式未改变；回滚代码不会恢复已写入的正文。

## AI 版本 2 升级与恢复

应用打开旧 AI 库时，先用 SQLite 一致性快照创建升级备份，再增加共享范围、任务检查点、冲突和活动结构。旧 ID、资源、修订历史和 Agent 范围保留。版本号高于当前支持范围时停止打开，不尝试降级重写。

日/周快照位于 AI 数据目录的 snapshots 中，默认保留 7 个日版本、4 个周版本；升级前快照另外保留。恢复整库的顺序：

部分 Windows 目录会在同目录重命名时返回跨磁盘错误。此时程序复制并同步完整快照后才移除对应的 `.pending-<文件名>`；有这个标记的目标文件仍未完成，不参与保留策略，也不能作为恢复来源。失败不会删除已有有效备份。恢复时同时检查对应标记，不要手动将未完成文件改名为有效备份。

1. 退出阅读器和连接本库的所有 Agent/MCP 进程。
2. 复制整个 ai-space 目录作为当前状态的副本，包括主库及 WAL/SHM（若存在）。
3. 将选中的一致性快照复制到一个新的空目录，命名为 ai-space.sqlite3。不要把旧 WAL/SHM 放入该目录。
4. 在新目录验证内容、历史、任务和资源。可用临时 MCP `--data-dir` 指向该目录检查，或保留原目录后再切换整个目录。
5. 验证通过后重新连接客户端；确认配置指向目标库，再继续写入。

JSON 备份版本 2 包含记录、资源、历史、检查点、活动、冲突和可迁移设置；旧版本 1 仍可导入。导入前验证结构，失败不部分写入。已有 ID 跳过，导入用于合并资料；需要准确回到过去状态时使用新空库导入或整库快照。来自其他机器的连接所有权、运行状态不导入。

Codex/Claude 配置修改前在原文件旁生成 `.moyang-<UUID>.bak`。一般使用接入页“移除 Moyang 连接”精确撤销；不要把整份旧配置直接覆盖到后来已添加其他服务的配置上。钩子信任由客户端管理，数据恢复不会代替信任。

## 正式渠道边界

正式应用标识是否沿用原版；旧版设置与草稿如何迁移；文件关联是否接管；签名密钥与更新源是否为新渠道；安装/卸载会影响哪些目录。开发版的隔离配置不应不经评审直接变为正式发布策略。
