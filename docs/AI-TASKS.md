# Moyang Reader — AI 任务队列

> 后续 AI 默认从上到下选择第一个 `TODO` 且没有开放 PR 的任务。一个任务一个分支、一个 PR。完成后改为 `DONE` 并附 PR 号；遇到新问题先确认当前代码和 Issues，避免根据旧审计重复开发。

## 使用原则

- 先解决真实用户路径和维护风险，再做抽象或新功能。
- UI 任务必须从“用户能否更快、更清楚、更稳定地完成动作”出发，不为改样式而改样式。
- 旧审计只作为线索，任何问题都必须在当前 `main` 重新确认；已关闭 Issue 不重新实现。
- 当前已经具备：文档返回历史、书签/文本批注、回收站与上一版本恢复、阅读历史/统计、中文拼音快速打开、阅读位置迁移。它们是回归基线，不是未来待办。

## 维护规则

- 队列只保留大约 10–25 个近期可执行任务；完成项及时移出，不让路线图变成历史档案。
- 新任务优先复用现有 Issue；如果 Issue 已关闭，先确认是否真的回归，再决定是否新开。
- 不需要任务 digest、审批 JSON、动态 state 文件或生成 NEXT。
- 用户临时改变优先级时，直接移动 Markdown 条目。
- UI/UX 新问题必须带最短复现路径和用户影响；“看起来可能不好”不直接进入开发队列。
