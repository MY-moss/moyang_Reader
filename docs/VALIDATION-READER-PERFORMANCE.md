# 阅读与闲置优化验证（0.13.1）

日期：2026-10-16。以 0.13.0 为基线。用户确认落实索引、草稿、撤销和 AI 闲置刷新；随后明确要求停止人为堆量压测。因此本轮以日常操作与数据结果为验收，不宣称大库吞吐、堆内存峰值或启动速度提升比例。

## 已实现

- 收藏、摘录和视图操作不触发正文逐文件核对。正文索引复用现有差量文件身份，串行合并变更；过时解析不发布，失败保留有效索引，单独提供重试。
- 原生书房请求与工作区搜索移到后台线程，保留文件授权和冲突规则。数据库首次初始化串行化，避免并行请求争用 WAL/表结构设置。
- 草稿逐篇存储，桌面使用阅读数据库，浏览器使用 IndexedDB。恢复列表只读取摘要，全文按需读取。旧草稿幂等迁移，保留旧副本；超限/磁盘错误不淘汰其他草稿。保存后清理核对预期正文，避免清掉后来输入。
- 连续短输入按位置与停顿分组撤销；每篇 16 MiB、所有会话 64 MiB 历史字符串预算，仍保留 100 步上限。裁剪只影响撤销历史，不删除正文或恢复草稿。
- AI 可见时轻量检查同一只读连接的 `data_version` 和下一次到期；内容未变时不重新统计、搜索或启动语义维护。窗口隐藏/离开空间后暂停，返回时核对；保留 MCP 外部写入发现。
- 修复 AI 自动保存期间点击手动保存会被忽略的问题，等待后继续保存最新草稿。

## 实际验证

- 单元与组件：90 个文件 / 294 项通过；随后新增的索引取消/重试用例单独通过。普通三文件场景确认收藏产生 0 次正文元数据检查，单文件变化只检查该文件。
- 原生：70 项通过，包含草稿重新打开、中文原文/草稿一致、迟到清理保留新稿、另一数据库连接写入与记忆到期发现。
- 浏览器：首次 93/94；唯一失败暴露 AI 自动保存与手动保存的交错，修复后相关 AI 两组共 16 项全部通过。覆盖旧草稿迁移、丢弃后重载、双空间草稿、输入法、冲突、技能资源和浅深色可访问性。
- 脚本：16 项通过。前端生产构建通过；静态检查无错误，保留已有焦点恢复 ref 警告和现有入口包体积提示。
- 桌面：12 个相关真实流程通过，包括中文草稿、迟到清理、多格式检索、双窗格同文件与输入法、外部冲突、重命名链接、收藏与回收站、关闭取消以及重载后的保存视图。

## 范围与恢复

启动方式和数据位置迁移入口不变；应用更新继续复用已有模型，不重复下载模型。新草稿表是附加结构，不改普通文件。降级前保存正在编辑的文档，旧版不读取新草稿表；旧 localStorage 副本用于核对迁移前内容。

浏览器突然终止或系统断电不能保证最后一刻的输入已经提交。预算是逻辑字符串容量，不等同于操作系统实际内存。没有进行新的极端规模、长时间空闲 CPU 或吞吐压测。

PDF 选区批注、批量来源核对、技能附件去重和向量存储替换仍为独立后续任务；本次不新增这些架构。真实 Codex/Claude 客户端的授权与模型服务验收继续沿用用户此前暂缓安排。
