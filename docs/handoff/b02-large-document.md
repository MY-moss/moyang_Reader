# B02 — 大文件阅读与编辑降级策略

## 结论

基于 Windows desktop E2E 的固定 Markdown 语料，`1 MiB` 文档在未做保护时进入 WYSIWYG、阅读模式和源码模式的往返切换无法在 10 分钟测试上限内完成；因此大于等于 `512 KiB` 的 Markdown 统一进入源文本模式。

超过阈值的文件仍可打开、编辑、使用 CodeMirror 原生查找和保存，但不会自动执行 Markdown 富文本渲染，也不会在保存后重新渲染。用户尝试切换到阅读或所见即所得模式时保留源文本并显示说明。

## 复测环境与语料

- Windows desktop E2E，固定 ASCII Markdown 段落，分别为精确 `1,048,576` 和 `10,485,760` UTF-8 字节。
- 每个文件包含一个确定性的搜索标记；保存步骤追加唯一标记后验证磁盘内容。
- 内存为 `moyang-reader.exe` 的 Windows Working Set；交互性为渲染器 50ms 心跳的最大间隔。
- 报告由 workflow 上传为 `large-document-benchmark-report` artifact；本机运行也会写入同名 JSON，结束后可清理。

## 实测结果

| 文件   | 首次可读模式 / 延迟 |        源码查找 |   保存 |          富文本切换 | 峰值 Working Set 增量 | 最大心跳间隔 |
| ------ | ------------------: | --------------: | -----: | ------------------: | --------------------: | -----------: |
| 1 MiB  |      source / 8.82s | 5.06s，1 个结果 | 40.46s | 40.05s，保持 source |              +7.3 MiB |        121ms |
| 10 MiB |     source / 15.70s | 5.70s，1 个结果 | 42.51s | 43.23s，保持 source |             +88.2 MiB |        703ms |

保存耗时包含 Windows 原子写入、桌面桥接和磁盘确认；它不再包含一次完整 Markdown 渲染。10 MiB 的心跳间隔仍然显示出明显交互压力，但没有进入富文本路径，也没有发生测试超时或写入失败。

## 实现边界

- 阈值只作用于 Markdown；纯文本本来就使用源文本模式，PDF、图片、Word 行为不变。
- 不修改 Rust 读取上限、搜索/索引算法、拼音匹配或 IPC 契约。
- 缓存中的大 Markdown 也会忽略旧的富文本快照，避免重新打开时恢复昂贵路径。
- 导出和打印的完整富文本渲染仍是显式操作路径；后续如需继续优化，应单独测量其取消与进度反馈。
