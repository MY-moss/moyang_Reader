# Moyang Reader 开发流程审计（归档）

> 审计日期：2026-09-03
>
> 事实基线：`origin/main@2a90448a065c2f5e98792106c93df2a3752bd79d`、GitHub 开放 Issue/PR、v0.10.14 发布状态
>
> 本文记录流程问题和整改决定，不授权当前任务；执行入口是 `npm run ai:context`。

## 结论

产品核心闭环已可用，下一阶段应优先处理安全披露、外部发布条件和可维护性，不宜直接扩大功能面。原开发流程的主要缺陷是“同一动态状态被复制到太多文件”：#112 已由 PR #443 完成并关闭，但 `NEXT.md`、提示词、交接、计划、待办和审计仍将它写成当前任务。

这会同时造成两个结果：AI 选错工作，且每次接手为确认事实读取数十万字节的重复历史。最终整改采用受保护 policy/plan 与可变 state 双层控制面；`NEXT.md` 只由结构化状态生成，根目录 `AGENTS.md` 提供自动加载的稳定规则。

## 新的上下文模型

```text
自动加载：AGENTS.md（稳定规则）
        ↓
每次运行：npm run ai:context（从唯一动态状态提取当前任务）
        ↓
按需读取：相关 Issue + 源码 + 测试 + 一个相似实现
        ↓
特殊任务：release-status / ROADMAP / REQUIREMENTS
        ↓
仅追溯：docs/handoff / CHANGELOG / Git / Release
```

事实冲突时按以下顺序处理：运行中的代码/测试 → 实时 GitHub → 受保护 policy/plan → 运行 state → 发布状态 → 摘要/路线 → 历史。生成摘要与 state 不一致时重新生成，不按摘要猜测。

## 文件职责

| 文件                         | 保留内容                         | 禁止内容                         |
| ---------------------------- | -------------------------------- | -------------------------------- |
| `AGENTS.md`                  | 平台、安全、启动、验证和交接规则 | 当前 Issue、固定 SHA、版本流水账 |
| `docs/ai/state.json`         | 唯一动态任务状态                 | 计划、权限、完整历史             |
| `docs/ai/plan-v1.json`       | 受保护的批准队列、依赖和验收     | 运行状态、临时候选               |
| `docs/NEXT.md`               | 从结构化状态生成的人类摘要       | 手工修改、独立动态事实           |
| `docs/AI-HANDOFF.md`         | 稳定版本、外部阻塞、最近结果     | 逐 PR 流水账、当前任务验收       |
| `docs/AI-TAKEOVER-PROMPT.md` | 可复制的稳定短提示               | 当前 Issue、版本、SHA            |
| `docs/ROADMAP.md`            | 产品阶段和依赖                   | 当前分支/PR/CI 状态              |
| GitHub Issue/PR              | 实时外部状态与讨论               | 本地权限替代、离线任务授权       |

`docs/REQUIREMENTS.md` 仍保留详细验收历史，但普通任务只读取相关标题区间。后续可按版本归档，它不再进入默认接手上下文。

旧 `tasks/plan.md`、`tasks/todo.md`、`docs/ISSUE-INDEX.md` 和一次性会话指标脚本已退役；历史由 Git 保存，`ai:check` 会阻止这些路径被重新引入为并行事实源。

## 预期效果

- 高频开发/交接文件从约 228 KB 降到受预算控制的分层上下文；默认只加载 `AGENTS.md` 和 `ai:context` 的当前任务摘要。
- 新 AI 不读取完整计划和历史，只按任务定位少量代码。
- 当前任务只改一处，合并后不会留下六份过期“下一步”。
- 交接不再要求不可靠的 Token 计数，也不复制完整 CI 日志。
- 自动检查会在控制文件重新膨胀、出现多个状态或提示词固定旧 SHA 时失败。
