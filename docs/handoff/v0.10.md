## #416 Windows 外部图标一致性切片（2026-09-02）

- 基线与范围：从 `main@b11539ea85bc816dbb9f002021084755d7c826b2` 的干净项目内工作树 `codex/icon-consistency-2026-09-02` 实现；只处理 Windows x64 外部图标一致性，不改变 Logo 设计、跨平台资源、工作区数据或 HTML/插件边界。
- 目标与用户价值：让应用内 Logo、可执行文件、NSIS 安装包、桌面/开始菜单快捷方式、任务栏和 Markdown/TXT 文件关联使用同一套确认资源，使安装、升级和打开文档时不再出现旧字母 M 或默认图标。
- 验收标准：`bundle.icon` 显式覆盖全部 Windows 图标；资源存在、非空、PNG 尺寸和 SHA-256 固定、ICO 目录和嵌入 PNG 尺寸完整且包含同源 256x256 图像；Release preflight 能拦截缺失、旧资源、旧 M SVG 和不安全路径；全新安装、覆盖升级、快捷方式和 `.md/.txt` 关联均指向新可执行文件；记录 Windows Shell 缓存边界。
- 实现与文件：`src-tauri/tauri.conf.json` 显式列出 16 个 Windows 图标资源；删除未被引用且含旧字母 M 的 `src-tauri/icons/icon.svg`；`scripts/release-check.mjs` 增加资源、ICO、同源 Logo 和路径门禁并接入 `validateProject`；`scripts/release-check.test.mjs` 增加有效/缺失/旧资源/ICO 哈希/不安全路径夹具；同步 `docs/NEXT.md`、`docs/UPDATE.md`、`docs/AI-HANDOFF.md`、本交接文件和任务地图。
- 依赖：既有 Logo PNG/ICO、Tauri NSIS 工具链和 Windows x64 环境；未增加运行时依赖。未来若有意更新 Logo，必须同步更新资源哈希与回归夹具。
- 风险与回滚：固定资源门禁可能提前暴露发布配置遗漏，Windows Shell 图标缓存仍可能需要 Explorer 刷新、重新登录或重启才能显示新图标；回退本切片提交即可恢复配置，不涉及数据迁移。
- 验证证据：release-check 单测 11/11、Prettier、JSON/差异检查、Tauri Windows x64 无安装包构建和本地 NSIS 包构建通过；Windows 提取出的可执行文件、安装器、桌面快捷方式和开始菜单快捷方式图标均为 32x32；全新安装与旧构建文件覆盖升级返回 0，`.md/.txt` 的 ProgID、DefaultIcon 和 open command 均指向隔离安装目录。验证目录已清理，本机原有安装引用已恢复。
- 发布边界：本切片只生成本地验收用 NSIS 包，不创建 v0.10.15 或任何 GitHub Release、签名文件、`latest.json`、Cloudflare 镜像；v0.10.14 稳定资产保持不变。一个分支只对应本切片的一个 PR，PR/CI 完成后停止。
