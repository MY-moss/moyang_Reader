# C02 — 文件异常恢复矩阵

日期：2026-09-19

## 结论

C02 收敛现有本地保存与恢复路径：保存失败先保留编辑区内容，并尽可能写入草稿恢复中心；原子写入失败不再静默删除仍可能包含用户内容的临时文件；外部删除与外部修改在界面上分开表达，避免给出会失败或误导性的“覆盖保存”入口。

本次不改变搜索索引、拼音匹配、IPC 命令名或版本号，也不把临时文件自动清理为“看起来成功”。

## 异常矩阵

| 场景 | 检测/证据 | 用户可观察结果 | 内容保护 |
| --- | --- | --- | --- |
| 磁盘空间不足 | Rust 根据 Windows/Unix 错误码和 `WriteZero` 分类；TS 识别稳定文案 | 明确提示空间不足；提示草稿恢复中心或“另存为” | 原文件不静默覆盖；编辑区保留 |
| 只读 / 写保护 | Rust 识别 `PermissionDenied`、写保护错误码；TS 识别只读文案 | 明确提示路径不可写 | 原文件不静默覆盖；编辑区保留 |
| 外部删除 / 移走 | watcher 事件后通过受控 `path_exists` 确认 | 显示“已被删除或移走”；只提供“另存为”和稍后处理 | 当前阅读/编辑内容保持；不提供误导性的覆盖保存 |
| 外部修改 | 既有磁盘版本核对与 watcher 冲突状态 | 重新载入、覆盖保存、另存为仍需用户选择 | 未保存修改不被静默替换 |
| 异常退出 / 关闭 | 既有关闭确认、beforeunload 和本机草稿快照；保存异常追加保存失败快照 | 可从草稿恢复中心比较并恢复 | 草稿不自动覆盖文件，恢复后仍需显式保存 |
| 原子临时文件残留 | 写入/刷新/替换失败保留同目录 `.moyang.tmp-*`；错误包含路径 | 不把失败伪装成完成；保留现场供人工恢复/诊断 | 原文件保持不变，部分写入不会丢失证据 |
| 上一保存版本 | `.moyang.bak` 改为临时复制后原子替换；既有上一保存版本入口保留 | 可查看差异并恢复到编辑区 | 不自动覆盖当前文件 |

## 实现边界

- `src/app/save-failure.ts` 只负责把跨平台保存失败归类为冲突、磁盘满、只读、缺失、权限或未知，并生成下一步提示。
- `document-session-controller` 在保存失败/冲突时先尝试写本机草稿；草稿失败时明确要求另存为，不清除 `modified` 状态。
- `ExternalChangeNotice` 对删除状态隐藏“重新载入”和“覆盖保存”，避免用户误以为原路径仍可安全写回。
- `src-tauri/src/commands.rs` 的文本/二进制原子写入与上一版本备份均使用同目录临时文件和替换；失败后的临时证据不做静默清理。
- 批量导出使用独立的导出临时文件生命周期，本次不改变其既有取消/清理契约。

## 验证

- Vitest：106 个文件 / 464 项通过。
- 相关保存恢复测试：22 项通过。
- `npm run build`、`npm run lint`、`npm run format:check` 通过。
- Rust `cargo fmt --check` 通过；Rust `cargo test --lib`：58 passed、1 ignored。
- Windows 原子替换失败测试确认目标目录未被覆盖，`.moyang.tmp-*` 内容仍可读取。
- 本机首次 Rust 编译曾因 C 盘实际 `os error 112` 中断；将本轮独立 worktree 的生成缓存移到 D 盘后重跑通过。这一事实同时作为磁盘满场景的环境证据，不将磁盘空间误报为代码失败。
- `desktop-e2e/smoke.e2e.mjs` 增加外部删除场景；Windows desktop smoke 已通过 18/18，包含该场景；启动时仅有非阻塞的磁盘空间诊断提示和 WDIO 清理警告。

## 风险与回滚

- 保留失败临时文件可能增加同目录隐藏文件，需要后续提供显式清理/恢复入口；本次不自动猜测用户意图并删除它们。
- 外部删除确认依赖 watcher 事件和一次受控存在性检查，文件在检查窗口内重新出现时按最新存在状态处理。
- 回滚时可恢复 `write_bytes_file_inner` 的错误清理策略和 controller 的保存失败回调；不会影响已有正文文件格式或 IPC 名称。
