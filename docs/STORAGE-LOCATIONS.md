# 存储位置与磁盘迁移

0.13 提供「设置 → 存储位置」。页面显示各类数据的**实际磁盘路径**、大小与迁移结果，支持把本应用资料移到 D、E 等本机磁盘。更换位置不会自动导入普通笔记，也不会把聊天混入 AI 记忆库。

## 使用步骤

1. 查看当前占用，点击「选择新位置」。程序使用所选文件夹下的 `MoyangData` 子目录，已有同名目录不会被覆盖。
2. 默认迁移应用资料、配置、草稿与界面缓存。可以勾选同时迁移本应用的便携模型；独立安装或自行配置的 Ollama 由其自身管理。
3. 关闭正在使用同一资料库的 Agent/MCP 连接；迁移模型时退出 Ollama 服务。应用会检查这些进程，不强制结束其他软件。
4. 点击「检查迁移」，确认范围与目标剩余空间。点击「保存并迁移」后，程序先保存编辑内容、AI 草稿、聊天和设置，再暂时关闭。
5. 复制并校验成功后，程序自动重新打开。回到存储页查看结果，确认实际路径已改变。

旧路径在 Windows 下保留为体积极小的目录链接，真实文件在新磁盘，已有 MCP 配置与 WebView 草稿仍可访问。再次迁移也支持原路径继续访问。不要把这些目录链接当成旧文件夹递归清空；删除链接前应先改好所有客户端配置。

## 范围

| 类型                           | 内容                                                                               | 处理                                       |
| ------------------------------ | ---------------------------------------------------------------------------------- | ------------------------------------------ |
| 应用数据                       | AI 数据库、长期记忆、技能资源、历史、自动快照、聊天/API 配置、扩展、阅读索引与设置 | 一起迁移，独立数据库结构保持不变           |
| 界面数据                       | 未完成草稿、工作区状态、WebView 页面缓存                                           | 关闭应用后整体迁移，不当作可随意删除的缓存 |
| 便携模型                       | 本应用运行程序旁的 models 目录                                                     | 可选；运行程序本身留在原位置               |
| 普通笔记、PDF 等原文           | 你添加的阅读库                                                                     | 不移动                                     |
| 手动导出备份                   | 你自己选择的位置                                                                   | 不移动                                     |
| 更新与程序                     | 程序所在 release / updates 目录                                                    | 保持原位置；小更新包不重复下载模型         |
| 其他 Agent / MCP / 独立 Ollama | 其他产品自己的资料                                                                 | 不改动，页面说明外部模型变量               |

C 盘可能仍保留 Windows 自身临时文件，以及迁移结果/计划等很小的记录。目标是把长期增长的本应用数据放到所选磁盘，不更改 Windows 或其他软件的存储规则。自定义 `OLLAMA_MODELS` 会被本应用尊重，不再被便携默认值覆盖。

## 失败处理与恢复

目标必须在稳定连接的本机磁盘，不能与源目录重叠。迁移前检查可写性、路径链接支持、正在使用数据的进程与剩余容量；至少需要当前数据大小加 64 MB。逐文件 SHA-256 校验后才切换全部路径，未校验成功不清理原数据。

锁定文件、磁盘拔出或复制错误会停止迁移，已切换的目录恢复原路径，应用重开后显示错误。失败的目标副本保留供检查，重试请选择其他空目录，或确认原位置可用后清理失败副本。清理原副本失败时会列出保留路径，新位置仍可使用。

迁移完成后必须保持新磁盘可用。若移动硬盘暂时断开，先接回；不要删除旧链接、创建空库或把空库误当成丢失资料。需要完整手工恢复时先退出应用及 Agent，备份实际数据目录，按已有[迁移与恢复手册](MIGRATION.md)恢复数据库；聊天另见[聊天指南](CHAT-EXTENSIONS.md)。

该功能以本项目维护的 Windows 桌面版为目标；浏览器预览只显示说明。实现依据 [Microsoft 的目录链接说明](https://learn.microsoft.com/en-us/windows/win32/fileio/hard-links-and-junctions)。现有路径兼容采用跨本机磁盘 junction，不依赖给每个 Agent 手动改路径。
