# WYSIWYG 序列化规范化

Moyang Reader 的 WYSIWYG 编辑器（Milkdown/remark）在保存时会把部分语义等价的 Markdown 写法改写为唯一规范形式。这是序列化器的既定行为而非数据损坏：语义完全无损，但字节会变化。我们选择固化这些规范形式（见 `e2e/smoke.spec.ts` 的 "serializes equivalent markdown styles to canonical forms"），让 Milkdown/remark 升级引起的规范化变化在测试中显式失败，而不是表现为用户文件里的神秘 diff 噪音；同时保持 `normalizeSerializedMarkdown` 只做剥离空行等与断言无关的最小处理。用户偏好原风格（如 `-` 列表符）时使用源码模式编辑。

已知规范化清单（全部语义无损）：

| 输入                               | 输出                                                       |
| ---------------------------------- | ---------------------------------------------------------- |
| `标题` + `====`（setext 一级）     | `# 标题`（ATX）                                            |
| `标题` + `----`（setext 二级）     | `## 标题`（ATX）                                           |
| `- item`                           | `* item`                                                   |
| `---`（thematic break）            | `***`                                                      |
| `\|窄\|表\|` 紧凑表格              | `\| 窄 \| 表 \|`（按内容重新填充宽度，分隔行为 `\| - \|`） |
| `[[双链]]`                         | `\[\[双链]]`（前双方括号转义）                             |
| `[[别名\|目标]]`                   | `\[\[别名\|目标]]`                                         |
| 嵌套引用紧凑写法（`>> 直接嵌套`）  | 层间补 `>` 空行                                            |
| 链接引用定义 `[a]: url` + 引用用法 | 内联化为 `[text](url)`                                     |

完全保真、不经规范化的语法：脚注、autolink、行内转义、有序列表、代码块、强调。

后续若要暴露用户可配置的序列化偏好（如 `bullet: "-"`），需同步更新本清单与上述 e2e 断言（参见 issue #157 方案 2/3）。
