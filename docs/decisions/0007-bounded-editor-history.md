# ADR 0007：编辑器统一有界历史

## 状态

已接受，随 v0.9.1 编辑稳定化切片实现。

## 背景

源码编辑器和 Milkdown 所见即所得编辑器都能修改同一个 Markdown 草稿。若继续依赖两个编辑器各自的原生撤销栈，切换模式后会出现撤销状态分裂、外部刷新被误记为本地输入，或者一次撤销绕过应用的未保存状态。用户需要的是“当前文档草稿”的恢复能力，而不是某一个编辑器实例的内部历史。

## 决策

- 在 `App` 层维护按文档路径隔离的 `EditorHistoryState`，保存 `past`、`present` 和 `future` 三段状态。
- 源码和 WYSIWYG 的 `onChange` 都通过同一个 `recordEditorChange` 入口；撤销/重做只通过 `undoEditorChange` / `redoEditorChange` 改变 `present`，再由 App 将新草稿同步回当前编辑器。
- 历史最多保留 100 个状态；新输入清空重做分支；重复源码不新增历史项。
- 打开、切换和重新载入文档时重置历史；保存不清空历史，因为保存后的继续撤销仍然应该产生新的未保存修改。
- App 在编辑器 DOM 的捕获阶段处理 `Ctrl+Z`、`Ctrl+Y` 和 `Ctrl+Shift+Z`，阻止 CodeMirror/ProseMirror 原生历史重复执行。阅读模式不处理这些命令。
- WYSIWYG 外部 `replaceAll`、源码编辑器的受控值同步和卸载前的最后一次序列化都必须经过去重，不能把同步动作当成本地输入。

## 后果

优点：模式切换后撤销语义一致，工具栏、命令面板和快捷键可以共享可用状态；历史内存有明确上限，不随长时间编辑无限增长。缺点：当前历史只属于本次应用会话，重启后不恢复；历史按源码快照记录，后续若要实现更细粒度的合并或跨重启恢复，需要独立设计持久化格式和隐私边界。

## 验收

- 源码和 WYSIWYG 编辑均可撤销/重做，切换模式后仍指向同一份草稿。
- 重新打开文档后撤销/重做按钮禁用；保存后撤销会将文档重新标为未保存。
- 外部刷新和编辑器销毁不会产生额外历史项；未知 Markdown 结构仍按安全策略回退源码模式。
