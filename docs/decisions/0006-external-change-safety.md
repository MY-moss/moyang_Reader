# ADR 0006：外部修改必须持续可见并在保存前复核

## 状态

已接受

## 背景

工作区 watcher 只能提供“文件发生变化”的事件，不能保证事件到达时用户仍看得到提示。原实现把“稍后处理”直接映射为清除提示状态；用户继续编辑并保存时，应用可能在没有第二次提醒的情况下覆盖其他程序已经写入的内容。应用自身的原子写入也可能产生多个延迟 watcher 事件，固定的写入前时间窗无法覆盖慢盘和同步盘。

## 决策

1. `OpenDocument.externallyModified` 是文档级持续状态；关闭横幅不清除它。标题、标签、正文信息和底部状态都保留可发现标记，用户可以从标记重新打开处理选项。
2. 当该状态存在时，普通保存必须停止并提供重新载入、覆盖保存、另存为三条明确路径。覆盖保存先经过应用内确认；重新载入沿用草稿备份和确认流程。
3. 即使 watcher 尚未到达，非覆盖保存也要在写入前读取磁盘文本，与文档最后一次已确认的 `source` 比较；不一致时转入外部修改状态，不写入。
4. 应用自身写入期间使用 in-flight 路径集合忽略 watcher 事件；写入 Promise 完成后才设置短暂抑制窗口，避免把写入前的固定时间当作完成信号。

## 后果

- 用户多一步明确选择，但不会因一次关闭提示而静默覆盖第三方修改。
- 保存动作会额外读取一次当前文本；这是低频的显式保存路径，优先保证数据安全。
- watcher 事件仍是增量提示机制，不作为保存安全校验的唯一来源。

## 验证

- `src/app/external-change.test.ts` 覆盖无关变更、自写窗口、自写进行中、自动刷新和冲突通知。
- `desktop-e2e/smoke.e2e.mjs` 覆盖冲突提示、隐藏后标记保留、普通保存拦截和确认覆盖保存。
