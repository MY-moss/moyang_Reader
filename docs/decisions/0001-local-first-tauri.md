# ADR-0001：采用本地优先的 Tauri 阅读器架构

## 状态

已接受

## 日期

2026-08-23

## 背景

目标是快速打开本地 Markdown，并逐步支持整个文件夹、DOCX、PDF、图片、导出和自动更新。应用需要 Windows 文件关联和本地文件访问，同时保持安装包和启动过程轻量，不依赖云端账户或服务端数据库。

## 决策

使用 Tauri 2 作为桌面壳，Rust 负责文件系统、目录扫描和边界校验，React/TypeScript 负责阅读界面和导出编排。Markdown 和 DOCX 在本地渲染；HTML 作为通用打印中间层；更新通过 GitHub Releases 提供，使用签名公钥验证安装包。

## 备选方案

### Electron

生态成熟，但基础安装体积和内存占用更高，与“快速轻量打开”的目标不一致，因此不采用。

### 云端阅读服务

便于跨设备同步，但会引入上传隐私、账号和服务成本，与本地优先定位冲突，因此暂不采用。

### 直接依赖系统 Word/PDF 应用

可以减少解析代码，但无法提供统一目录、链接、标签、搜索和导出体验，因此只把系统打印作为 PDF 交付路径的一部分。

## 后果

- 需要同时维护 Rust 命令层和前端桥接层，并为两侧补测试。
- 文件访问权限、远程资源和更新器安全边界必须持续审计。
- 未来可以在不改变本地阅读核心的情况下增加插件、同步和跨平台打包。
