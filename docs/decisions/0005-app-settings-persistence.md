# ADR 0005：应用设置的双层本机持久化

## 状态

已接受，随 v0.10.3 设置稳定性切片实施。

## 背景

阅读字号、正文宽度、主题、语言、导出排版和面板布局等设置原先分别写入浏览器 `localStorage`。这条路径在浏览器刷新测试中可用，但桌面端遇到存储不可用、数据损坏或 WebView 迁移时会静默回退到默认值，用户无法判断设置是否真正保存。

## 决策

- 前端维护一个版本化的统一设置快照，覆盖阅读偏好、主题、语言和面板布局。
- 写入 `localStorage` 后立即回读校验；失败不得显示成功。
- Windows Tauri 端另外把同一快照写入应用配置目录的 `settings.json`，通过临时文件、刷新和原子替换完成写入。
- 启动时比较统一快照的 `savedAt`，优先使用较新的本机快照；旧版本的分散键仍作为迁移来源，不被空配置覆盖。
- 应用配置文件只包含偏好和 UI 元数据，不包含文档正文、密钥或用户选择的文档副本。
- 保存状态在设置面板内显示，避免使用会推动主布局的全宽通知条。

## 后果

- 设置跨桌面重启更可靠，并且失败原因对用户可见。
- 增加一项很小的 Tauri IPC 接口和一个受限的配置文件，维护成本低于引入数据库或重量级状态库。
- 未来增加设置字段时必须保持解析默认值和版本迁移；不应直接把不受信任的配置值用于文件路径或命令执行。
