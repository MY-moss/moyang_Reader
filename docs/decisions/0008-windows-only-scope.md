# ADR-0008：收敛为 Windows x64 单平台产品

## 状态

Accepted

## 日期

2026-08-26

## 背景

Moyang Reader 的核心用户场景是 Windows 本地快速阅读和编辑 Markdown。当前功能集中在 Windows 文件关联、单实例路径传入、目录监听、原生文件对话框、NSIS 安装包、签名更新和真实 Tauri 桌面回归。继续维护 macOS/Linux 的构建前置、路径差异、桌面 E2E、签名、公证、安装包和更新链路，会增加 CI 时间、测试矩阵、文档分支和 AI 交接成本，但目前没有对应的用户验收需求。

## 决策

在 v1.0 前把 Windows x64 定义为唯一产品和发布平台：

- 公开安装包、Release、更新 manifest、签名和 Cloudflare 镜像只提供 Windows x64 NSIS 资产；
- 默认 CI 只运行 Windows 质量门禁，覆盖前端、浏览器、真实 Tauri 桌面、Rust 和发布检查；
- 浏览器版继续作为开发预览和 Playwright UI 测试环境，不单独承诺桌面支持；
- macOS、Linux、Windows ARM、移动端、跨平台文件关联和跨平台自动更新暂不开发；
- 现有跨平台 Rust/Tauri 抽象不主动删除，除非它们明确增加 Windows 构建体积、启动时间或维护负担；
- RustSec 依赖审计可以保留 Ubuntu runner，因为它是低频的平台无关安全检查，不是 Linux 产品构建。

## 原因

- 减少每个 PR 的 runner、缓存、依赖安装和失败诊断成本；
- 让测试、用户文档、安装包和自动更新只围绕一个真实平台形成闭环；
- 将有限开发资源用于 Windows 下的启动速度、编辑器可靠性、文件夹工作区、导出和更新体验；
- 避免为了“看起来跨平台”而提前引入抽象、条件分支和未验证承诺。

## 代价与缓解

- 代价：非 Windows 用户暂时不能获得正式安装包和支持。
- 代价：未来重新开放平台时需要重新建立构建、路径、签名和桌面回归矩阵。
- 缓解：保留不影响 Windows 的现有跨平台抽象；平台相关代码继续使用清晰的边界，未来可按新 ADR 恢复。
- 缓解：在 README、平台文档、路线图、发布政策和 AI 交接中明确“不支持”而不是留下模糊的“Windows 优先”表述。

## 不采用的方案

### 继续默认运行 macOS/Linux preflight

不采用：它只能证明部分编译兼容性，不能替代真实桌面签名、公证、文件关联和更新验收，却会为每个 PR 增加 runner 和维护成本。

### 删除所有跨平台代码

不采用：删除本身会制造回归和迁移成本；只要代码不影响 Windows 产物，就保留并停止新增平台承诺。

## 重新开放条件

只有在出现明确的用户需求、维护者确认预算和可执行的真实平台验收资源后，才通过新的 ADR 重新开放目标平台；新 ADR 必须同时给出构建、安装包、签名、自动更新、文件关联、桌面 E2E 和持续维护责任。
