# 代码、运行与 GitHub 同步检查

目标：在现有重构结果上修复可复现的数据与运行问题，保留原工程、本机数据及启动方式，将可审阅的源码与文档同步到 GitHub。

## 场景与验收

- [x] 快速切换文档、双窗格编辑、关闭标签时，最后一段输入写回所属文档，不覆盖另一篇笔记。
- [x] Windows `npm run desktop` 正常启动；命令不依赖通过 shell 启动 `.cmd` 文件。
- [x] 客户端配置更新中途失败后可以重试，保留原配置与本应用写入部分的所有权。
- [x] 新包先完整生成再公布位置；构建或打包失败不修改正在使用的上一份包。干净检出不依赖本机测试报告。
- [x] 桌面烟测隔离笔记设置、书房、AI 数据及 WebView；验证本次构建的程序，不连接占用端口的旧服务。
- [x] 检查前端、Rust、运行脚本与完整操作流程；浏览器和桌面构建顺序执行。
- [x] GitHub 仅同步重构源码及必要文档，排除依赖、模型、本机数据库、配置备份和原始测试数据。
- [x] 从远端主分支建立独立提交，保留当前旧工程所有未提交改动；推送后核对提交与 PR。

## 范围与风险

前端审查保存、草稿、异步请求和双窗格；后端审查迁移、恢复、MCP、范围过滤、客户端配置；主流程检查启动、构建、便携包与交付。只修复有代码证据或复现结果的问题。数据写入路径变化必须有回归用例，不使用个人数据做破坏性验证。

回退代码不删除用户数据。新便携包使用独立目录，旧包继续可用。GitHub 同步通过独立分支与 PR，不覆盖主分支或旧工程工作区。
