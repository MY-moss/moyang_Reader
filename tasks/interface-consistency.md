# 页面与交互一致性修复

目标：让当前页面、导航和表单状态相符，保留现有暖白墨绿视觉与数据边界。

## 执行与验收

1. 走查阅读、AI、扩展、设置和 API 页面；记录真实画面及可复现的操作问题。
2. 修复导航选中、窄窗入口和筛选恢复；验证往返切换不丢草稿，当前入口唯一。
3. 统一设置控件、页面标题与图标；API 未保存切换提供继续编辑、放弃、保存后继续。
4. 运行相关交互回归、完整前端检查与浏览器流程；集中检查浅深色、1440/900/720 窗口和键盘操作。
5. 更新使用说明与验证报告，同步 GitHub，交付本次构建。

## 已确认问题

- 全局设置或市场打开后，AI/阅读的旧页面仍在侧栏标为当前页。
- 主题为无样式循环按钮，部分设置动作也未使用统一按钮样式。
- 设置遮住窄窗导航入口；页内返回和全局导航缺少一致性。
- 扩展搜索随列表滚走；无结果缺少直接清除条件入口。
- API 服务切换或返回会直接丢失尚未保存的输入。
- 窄窗 AI 详情打开时，搜索动作试图聚焦隐藏的列表输入框。

## 验证结果

原实现五条问题路径均复现失败，修复后新增六条交互回归通过。前端 311 项、脚本 16 项、架构与生产构建通过；24 个页面状态经浅深色与窄窗检查，无横向溢出、页面错误或自动无障碍违规。完整浏览器检查中旧用例仍匹配字符箭头，已同步为图标替换后的可访问名称“返回列表”；最终重验、桌面包和云端结果见对应发布页。原始页面证据保留在本机 `.local/interface-audit/`。
