# v0.7–v0.8 快速推进计划

## 目标

在不改变本地优先和轻量启动定位的前提下，继续完成 Moyang Reader 的基础产品能力，形成可发布的 v0.8：大文档阅读更顺滑、恢复和导出更可靠、格式接入可扩展、核心界面可访问、更新与跨平台准备可持续维护。

本计划不要求每个小切片都发布安装包。每个切片必须保持构建和测试可用，并保留 Git 提交；阶段性功能批次再同步到 GitHub，稳定后统一发布 v0.8 安装包。

## 已有基线

- v0.6 已包含多工作区挂载与切换、标签页和阅读位置恢复、草稿恢复、CodeMirror 源编辑、工作区搜索候选索引、批量 PDF/DOCX 导出取消、打印预览、关系图和签名更新主链路。
- 当前主线受保护，提交通过 `Quality checks` 后经 PR 合并。
- Cloudflare 镜像代码已具备发布触发和 Release 资源映射逻辑，凭据仍由仓库维护者在 GitHub Secrets 中配置；开发阶段继续保留 GitHub Release 回退。

## v0.7：阅读体验与稳定性收口

### Slice 1：大文档渐进式阅读渲染

- 目标：对超长 HTML 拆成安全的顶层块，使用浏览器 `content-visibility` 和块级边界降低首屏布局、滚动和搜索后的重排成本；短文档保持现有输出。
- 范围：纯函数切块、阅读组件接入、滚动/目录/打印导出行为回归测试。
- 不做：把 Markdown 语法粗暴按字符串截断；导出和打印仍使用完整 HTML。
- 验收：短文档输出一致；长文档块边界不破坏表格、代码、列表和标题；已有阅读点击、目录跳转、文内搜索测试通过。

### Slice 2：恢复中心与会话可靠性

- 目标：从单个草稿提示扩展为可查看的本地恢复列表，明确恢复、丢弃和清理规则；不保存云端正文。
- 范围：草稿恢复纯逻辑、过期/上限清理、恢复面板入口、单测和浏览器 e2e。
- 不做：账号同步、后台上传或未经用户确认的覆盖写入。
- 验收：异常退出后能恢复对应文档；路径失效、正文已一致、超限草稿不会污染启动；恢复操作可逆到当前编辑状态。

### Slice 3：搜索索引持久化和进度反馈

- 目标：为现有 bounded in-memory index 增加按工作区的本地元数据快照和重建状态，冷启动优先复用仍有效的索引，不牺牲失效回退。
- 范围：索引版本/文件 mtime 校验、取消与重建状态、Rust 单测；只写应用缓存目录，不写入工作区正文。
- 不做：此阶段引入 Tantivy 或复杂查询语法。
- 验收：文件增删改后结果不陈旧；缓存损坏自动重建；大型工作区启动时 UI 可见状态且不阻塞打开文档。

### Slice 4：打印与导出完成度

- 目标：补齐封面/页眉页脚/页码和批量导出失败清单的用户反馈，继续复用现有 PDF 打印链路。
- 范围：导出选项数据模型、打印预览提示、失败清单复制/保存、纯逻辑测试。
- 不做：本地嵌入完整 PDF 引擎；系统打印对话框仍负责最终 PDF 生成。
- 验收：单文档和批量导出均能看到使用中的纸张、方向、边距和失败项；原 Markdown 不被修改。

### Slice 5：可访问性自动化基线

- 目标：把 critical/serious 级 a11y 检查纳入 e2e/CI，并记录读屏冒烟清单和主题对比度结果。
- 范围：axe Playwright 检查、关键页面选择器、贡献指南。
- 不做：把 minor 级历史样式问题一次性扩展成大规模 UI 重构。
- 验收：空状态、阅读视图、快速打开、设置/打印对话框有自动化检查；检查失败能阻止质量门禁。

## v0.8：可扩展与可维护发布

### Slice 6：内置文档适配器注册表

- 目标：新增格式时只需注册适配器，不再让核心 App 维护多处分支；Markdown、纯文本、HTML/DOCX 保持现有行为。
- 范围：适配器契约、注册表、内置适配器迁移、动态加载边界、契约测试。
- 不做：加载工作区内任意 JavaScript 插件；外部插件执行保持明确禁区。
- 验收：扩展名识别、可编辑能力、渲染和导出能力通过统一契约；核心入口 chunk 不因 DOCX 适配器迁移而变大。

### Slice 7：本地可迁移设置与工作区清单

- 目标：提供无账号、无云端依赖的设置/挂载清单导出与导入，为未来可选同步提供稳定数据格式。
- 范围：版本化 JSON bundle、路径校验、预览模式下载/桌面保存、导入冲突提示。
- 不做：默认上传正文、账号体系或选择云厂商；真正云同步等用户明确 provider 后再做。
- 验收：导出的 bundle 可在另一台机器导入；不会自动读取/覆盖不在用户确认范围内的正文。

### Slice 8：更新回滚提示和发布自检

- 目标：更新失败或版本回退时给出可理解提示，发布自检覆盖 Release manifest、签名文件、镜像回退和版本一致性。
- 范围：更新状态纯逻辑、发布检查脚本/测试、文档化回滚步骤。
- 不做：上传私钥、绕过签名校验或静默降级安装。
- 验收：错误分类可操作；`latest.json`、安装包和签名缺失时发布检查失败；GitHub Release 仍可作为镜像故障回退。

### Slice 9：国际化基础与跨平台构建前置

- 目标：建立 zh-CN/en-US 文案入口并迁移核心壳层；为 macOS/Linux 添加构建矩阵和能力差异检查，不承诺未验证平台的生产安装包。
- 范围：核心导航、设置、更新、导出文案；CI 矩阵、路径/文件关联/更新器检查清单。
- 不做：一次性迁移全部历史文案或在无签名/无实机验证时宣称跨平台稳定。
- 验收：核心界面可切换两种语言；CI 能明确报告各平台编译和未支持步骤。

## 每个切片的完成标准

1. 先补复现/契约测试，再实现最小改动。
2. 至少通过受影响单测、构建、lint、格式检查；涉及桌面或发布链路时增加对应检查。
3. 记录变更、已知限制和下一切片入口。
4. 本地提交后阶段性推送分支，使用 PR 合并，不直接覆盖受保护的 `main`。

## 明确保留的产品决策

- 默认本地优先，文档正文不进入同步 bundle，不引入账号系统。
- 外部插件不允许直接执行工作区内任意脚本；v0.8 只做内置适配器注册化。
- Windows 继续作为当前稳定发布平台；macOS/Linux 先做构建和行为验证，再决定正式安装包渠道。
- 小问题和不影响主流程的 Issues 不阻塞 v0.8 主线，按影响范围在稳定发布前集中处理。
