# Moyang Reader 全项目重构计划

日期：2026-10-15。基线：父目录当前工作副本（包括未提交代码），版本 0.10.7。

## 目标与约束

保留本地文件阅读产品的完整能力，在独立目录重组前端、桌面后端、界面和文档。用户明确要求沿用现有启动方式；保留 `npm run dev`、`npm run desktop`、`npm run build`。界面采用暖白、清晰排版、阅读优先的书房风格。原项目不覆盖、不清理、不提交。

## 执行顺序与验收

| ------------ | ------ | --------------------------------------------------------------------- | ---------------------------------------------------- |

| 独立基线     | 盘点   | 新目录完整源代码、锁文件和工程配置                                    | 所有导入在新目录内解析；保留原目录哈希               |

## 开发流程

1. 每项从用户场景和验收条件开始，先读相关模块、测试和接口。
2. 一个变更只对应一个职责边界；涉及数据/文件操作时先保留安全性回归用例。
3. 先运行变更涉及的测试，再通过全量单元测试、构建、静态检查。
4. 改变交互后执行浏览器用例及浅色/深色、紧凑/宽屏检查。
5. 桌面边界变更必须经过 Cargo 检查；真实桌面能力需要桌面环境验证。
6. 每个检查点更新 `tasks/todo.md` 与 `docs/VALIDATION.md`；失败保留原因和重现方式。
7. 发布前另行验证安装、签名、更新、关联与卸载；开发通过不等于发布通过。

## 风险控制

- 新旧项目共享现有启动端口：不要同时运行同一种开发服务。
- 用户的本地文件是唯一真源：保留路径授权、原子写入、外部修改确认、草稿恢复。
- 自动更新可能装回旧版：重构开发版使用独立应用标识，移除无发布源的更新入口。
- 旧文档存在版本与能力描述漂移：以源码及本次测试为依据，旧资料存档而不充当新版指南。
- 功能大量跨模块协作：以现有回归测试保护行为，类型化连接状态与业务操作，不引入第二套状态源。

## 完成标准

新目录可独立安装、启动和构建；前后端职责清晰；重做欢迎页和工具层级；核心功能回归无新增失败；文档覆盖理解、开发、使用、迁移与验收；准确说明桌面发布与手工验证的剩余边界。

## 追加阶段：深度重构和规划落地

用户已授权直接实现实用的后续规划并清理无效功能。新增顺序：稳定保存/刷新/位置 → 偏好和导出模板 → 属性与块引用 → 命令和关系图 → 大目录与无障碍 → 全量回归 → 本地桌面产物。每项的对应关系、删除理由和验收记录在 `docs/ROADMAP-DELIVERY.md`。软件绝对无缺陷无法被有限测试证明，交付以实际通过的场景和明确边界为准。

## 第二阶段：AI 知识、长期记忆和技能

前置门禁：第一阶段验证报告完成，正常桌面可执行文件构建成功。三类信息与日常笔记隔离；外部 Agent 通过 MCP 读写。由本项目自行选择和比较开源参考。

1. 研究多个项目的实际文档、存储/召回实现、MCP 接口和许可证，形成有来源的取舍记录。
2. 定义独立 AI 空间的数据、检索、记忆修订/合并/归档、技能导入导出、MCP 使用流程；先记录规范和验收标准。
3. 实现共享持久层和检索，验证跨进程读写、中文与英文、作用域过滤、重复记录和历史恢复。
4. 实现 MCP 的实际读写工具和客户端连接，验证初始化、调用、错误与服务重启后的持久化。
5. 实现简洁的知识/记忆/技能界面及接入页；切换空间保留阅读草稿，读写变更可见。
6. 验证端到端场景、补齐用户和开发文档，重新构建最终桌面产物。

个人产品取舍：不增加团队、账户或企业审批。记忆以可解释、可编辑、可追溯的内容帮助 Agent，不宣称自动训练模型。无法真实调用的功能不做成假按钮。
