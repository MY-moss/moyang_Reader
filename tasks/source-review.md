# 知识来源批量核对

用户场景：文件与网页导入后仍保存独立快照；资料积累后，用户能按项目检查来源变化，查看差异后逐条更新，不依赖额外模型。

## 实施与验收

1. 分页读取已导入知识的来源元数据，按项目筛选；不加载正文、附件或历史，不触发嵌入。
2. 在近期活动的“来源更新”中主动开始检查，每次最多读取两个来源；支持停止、重试、状态筛选。无法读取与未变化明确区分。
3. 集中预览当前快照和来源正文，确认后复用原有修订检查与历史保存。检查本身不修改数据库，不用失败或空正文覆盖有效快照。
4. 普通笔记、手动记忆和技能不进入来源队列。仅有文件名的浏览器导入提示重新选文件；网页检查说明会访问来源网站。
5. 回归范围、分页、停止与迟到结果、部分失败、并发修改和更新后的历史；检查真实桌面的文件变化、网页来源与重启读取。

内存取舍：批量结果只保留轻量元数据和状态，打开比较时重新读取该来源，保证比较对象新鲜；不缓存全部正文。检查时间只描述本次会话，不制造无内容变化的修订。

原方案的两个真实 Agent 生命周期验收继续按用户安排暂缓。批量来源核对不能替代该项验收。
