# 原项目理解与提炼

## 分析基线

2026-10-15，父目录 Moyang Reader 的当前工作副本。`package.json`、Cargo 和 Tauri 配置版本均为 0.10.7；旧 README 仍描述 0.10.5，证明版本说明存在漂移。原目录含未提交修改，特别是正文右键、工作区详情、标签页和编辑器，因此没有直接从 Git HEAD 复制。

基线清单见 [source-manifest.json](baseline/source-manifest.json)，前端迁移映射见 [frontend-mapping.json](baseline/frontend-mapping.json)。清单记录原路径、大小及 SHA-256，用于核验源工程完整性。未复制 `.git`、依赖目录、产物目录、工作树或构建缓存。

## 产品的核心

Moyang Reader 是以本地文件为真源的文档阅读与轻编辑工具。阅读库是用户选择的文件夹，文件仍留在原位置；它不是必须导入私有数据库的笔记系统，也没有账号与云端同步服务。

价值链为：找到本地资料 → 打开并阅读 → 通过目录、搜索和关联理解内容 → 必要时编辑 → 保存或导出 → 下次继续阅读。

主要用户场景：阅读 Markdown 知识资料；浏览包含 TXT、Word、PDF 和图片的文件夹；用双链连接笔记；对阅读中的文字做少量修改；将资料导出为可分享的 HTML、DOCX 或 PDF。

## 值得保留的设计

- Markdown 文本是持久化真源，编辑器内部结构不成为独立存储格式。
- 渲染结果经过清洗；远程资源默认关闭，避免打开本地文档时隐式联网加载图片。
- 读取和写入授权分开；单文件授权不等于任意目录写入权限。
- 文件写入使用临时文件替换与备份，外部修改有确认，未保存修改有草稿恢复。
- 工作区先显示文件，再建立关联索引；监听采用差量刷新，搜索有缓存及有界索引。
- 已有较完整的单元和集成测试，应保留作为重构保护网。
- 浏览器与桌面能力边界明确，不通过浏览器模拟原生路径权限。

## 发现的问题

| 问题                | 证据                                                       | 重构响应                                                                      |
| ------------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 应用职责集中        | App.tsx 4,843 行，管理大量状态、监听、操作和 JSX           | 拆出状态、16 个职责 hooks、应用组合与 6 个视图                                |
| 后端混合职责        | commands.rs 4,640 行，权限、搜索、文件、PDF 与测试同处     | 分为 access/search/dialogs/settings/files/watcher/workspace/index/entries/pdf |
| 样式难定位          | styles.css 4,577 行，布局、编辑、弹层、主题、打印交错      | 按职责拆分，明确书房主题和打印优先顺序                                        |
| UI 密度与任务不一致 | 顶部大量操作，设置和导出夹在工具层级中                     | 固定主操作、快速打开入口、按文档状态显示保存                                  |
| 默认进入编辑        | reader-mode.ts 对 Markdown 返回 wysiwyg，对文本返回 source | 新打开文档统一进入阅读，编辑需明确操作                                        |
| 文档与实现漂移      | README 版本滞后，部分说明与实际打开行为不一致              | 新文档以代码与验证为准，旧文档作为历史基线                                    |
| 并存风险            | 同标识、更新源与文件关联可能影响原版                       | 开发版独立标识，移除旧发布更新配置和关联                                      |

行数取原工作副本，含空行。重构重用已有解析、索引和安全算法；目标是改变职责组织与体验，不通过重写成熟算法制造额外风险。

## 能力边界

当前产品维护 Windows x64。HTML 是内部渲染/导出格式，不把任意 HTML 文件当成已支持的输入类型。Word 主要是阅读和导出，不提供完整 Word 排版编辑。PDF 使用预览与系统能力，不做 OCR 或 PDF 内容编辑。浏览器预览不支持真实工作区文件写回。跨平台发行、云同步、账号不在本次需求内。用户新增的 AI 知识库、长期记忆库、技能库与 MCP 将在阅读器重构全部验证后，作为第二阶段独立空间实施。
