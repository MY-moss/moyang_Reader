# 中文检索实测

测试时间：2026-10-16。本报告只描述本机实际运行结果，不把有限测试等同于任意问题都能正确回答。

## 环境与样本

使用 Ollama 0.40.4、`qwen3-embedding:0.6b`，CPU 推理；本机约 32 GB 内存、16 个逻辑处理器，Intel Iris Xe。模型已实际下载并通过本地 `/api/embed` 生成向量。没有重排模型或额外总结模型。

隔离数据库包含 45 条中文资料、65 个文本片段。80 条用例覆盖精确查找（15）、语义改写（15）、长文多证据（10）、时效更新（10）、项目和 Agent 范围（15）、无答案（15）。每条保存预期记录、实际命中、来源片段与耗时。

运行入口：`node scripts/evaluate-ai-search.mjs`；已有样本与索引可用 `--reuse` 复测。原始资料与逐条结果在 `artifacts/ai-evaluation/`。测试不读取用户的日常笔记。

## 结果

| 指标                     |     实测 |
| ------------------------ | -------: |
| 最终通过                 |  80 / 80 |
| 查询耗时中位数           |   241 ms |
| 查询耗时 P95             |   374 ms |
| 首次建立 65 个片段的向量 | 150.5 秒 |

02:20 的最终复测仍为 80/80；此前低负载运行中位数 202 ms、P95 281 ms。编译并行时 CPU 负载会影响延迟。最后一次复测的 `index_ms: 31` 表示索引已经齐全时的检查耗时，不能当成首次索引速度。首次完整结果保存在 `results-baseline.json`。

初始版本通过 76 / 80。弱相关中文词和长文的共同词使部分问题排序错误，也使无答案问题返回看似相关的内容。修改后保留语义相似度、限定弱词命中的影响，并按库内标题词频识别有区分度的标题词。中间版本 79 / 80，最终 80 / 80；中间结果也保留，便于对照。

## 如何理解这些数字

这是围绕已确认使用场景构建、并用于调试的回归集，**不是独立盲测集**。80 / 80 表示这些预期行为通过，不表示所有中文问法都能召回正确资料。小型样本也不代表数万篇资料的性能。客户端会先显示关键词结果，语义结果随后补充；模型不可用时保留关键词检索，并明确提示。

内容不变时复用片段与向量；改标题、标签不重新嵌入正文。检索只加载资源清单以外的文本属性，资源正文按需读取；取消查询会中断正在等待的嵌入请求。项目范围、旧 Agent 私有范围、归档和有效期在检索过程中执行，不依赖最终页面隐藏。
