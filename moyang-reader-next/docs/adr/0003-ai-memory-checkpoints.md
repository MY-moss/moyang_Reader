# ADR 0003：AI 来源、共享范围与任务检查点

状态：已实施，客户端端到端验收单独跟踪。日期：2026-10-16。

阅读器验收完成后扩展现有 SQLite AI 库，不引入独立记忆服务器。设计参考 TencentDB-Agent-Memory 的候选去重、来源证据和读写分离，以及 OpenViking 的分层读取、原始轮次检查点；研究依据见 `RESEARCH-AGENT-MEMORY-2026-10.md`。

## 数据边界

数据库版本从 1 升到 2，升级前通过 SQLite `VACUUM INTO` 保存包含 WAL 已提交数据的完整快照。已有 ID、修订、资源和范围不变。日常快照保留 7 个日版本与 4 个周版本，升级快照单独保留。便携 JSON 备份版本 2 增加设置、检查点、冲突与活动，仍接受版本 1。损坏结构在事务写入前拒绝。

`sharing=legacy` 保留原项目和 Agent 边界；`global` 全局共享；`project` 在指定项目跨 Agent 使用。新界面及检查点产生的内容默认明确选择全局或项目，旧 MCP 保存接口省略该字段时仍采用 legacy。`agent` 对共享内容表示来源，对旧内容仍参与范围过滤。

显式导入产生 `snapshot`，包含来源 URI、原内容指纹、格式、时间和页码/段落/引用文字。检查来源更新只展示差异，用户采用后产生新修订。普通笔记不会由 MCP 自动遍历。

## 检索与资源

关键词结果先展示，语义结果随后补充；过期请求不能替换新查询。每个结果最多携带 4 个片段和来源位置。语义查询在数据库按范围筛选后计算，查询向量缓存有 5 分钟期限、128 项上限。嵌入只依赖正文片段，相同片段复用原 ID 和向量；标题、标签、范围变更只更新关键词索引和记录属性。向量版本键包含 body-v2，旧模型向量不会被误用。

MCP 搜索返回摘要与片段，读取记录返回正文和资源清单，附件按路径单独读取。修订详情同样不返回附件字节。

## 自动沉淀

检查点唯一键为客户端、会话和原始用户轮次。状态为 pending、completed 或 no_new_information。Stop 钩子最多申领一次补充处理，中断留下待处理记录。当前 Agent 根据任务结果决定是否有值得长期保存的新信息；不增加总结模型。

一次 conclude 操作在同一事务内处理全部决定。明确更正带来源证据和当前版本号，修改记录并保留历史。推测矛盾只保存待处理提议。技能改进要求已有技能、成功/失败结果和具体证据。精确重复不生成重复沉淀活动。

活动保存修改前后版本、原因、证据与检查点。撤回和恢复均新增修订；如果内容后来已被其他人修改，拒绝静默覆盖。客户端配置成功、MCP 实际调用、钩子实际运行分别记录，见 ADR 0004；真实客户端授权与模型服务阻碍见验证记录。

## 编辑与关闭

AI 草稿按文档保存到 IndexedDB，正文/属性与资源分开，资源引用未变时不重写附件。编辑、切换分类和查看其他内容互不覆盖草稿。Markdown 与阅读器共用编辑器；保存前同步编辑器尚未发出的最后一次输入。原生关闭流程等待当前保存与草稿事务，草稿冲突通过比较、合并或另存处理。
