# 文档会话与窗格分别管理

状态：已接受，2026-10-15。

## 背景

原界面只有一份活动文档状态，切换会重新读取并重置编辑历史。直接创建第二份阅读器会重复窗口监听、设置写入和文件保存，并使同一文件出现相互覆盖的草稿。

## 决策

应用只创建一个阅读器协调器。按规范化路径管理文档会话；窗格保存自身的标签、位置和活动文档。文档内容、基线、草稿、保存队列归文档会话，窗口事件与全局设置归应用。两个窗格打开同一文件时共用会话；编辑焦点仅属于当前窗格。

## 影响

切换无需丢弃草稿；关闭、自动保存与外部变更必须检查所有未保存会话。既有文件授权、原子写入、外部变更和恢复流程继续使用。普通笔记与 AI 内容不合并真源，仅共享编辑交互组件。
